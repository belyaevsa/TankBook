## Background you need (already gathered – do not re-derive)

`GET /v1/config` returns `{ "document": {...}, "signature": "<base64>", "version": N }`.
The signature is Ed25519 over the **canonical bytes of `document`**.

The canonicalization contract is specified in the doc comment of
`backend/src/Tankbook.Api/Config/ConfigCanonicalizer.cs` as six numbered rules. **Read that file.**
Your Swift implementation must match it byte for byte. Restated:

1. The document is a single JSON object.
2. Object members are emitted in **lexicographic ordinal order of their keys, at every nesting level**.
3. Compact – no insignificant whitespace. `:` after each key, `,` between members and array elements.
4. Strings in minimal escape form: escape only `"` and `\`, control characters as `\uXXXX`, everything
   else raw UTF-8. **Non-ASCII is NOT escaped** – Cyrillic stays Cyrillic.
5. **Numbers are emitted EXACTLY as their source token.** `0.75` stays `0.75`; `1e3` stays `1e3`;
   `9007199254740993` stays exact. Never re-serialize from a parsed `Double`. **This is the one place
   naive implementations diverge, and it is why this task exists.**
6. Array element order is preserved.

Read `ios/Sources/TankbookCore/Sync/JSONValue.swift` first. If it already preserves raw number tokens,
build on it. If it parses numbers into `Double`/`Int`, **do not use it here** – it will silently destroy
rule 5. In that case write a dedicated minimal JSON tokenizer for config that keeps each number's source
substring verbatim. Say in a comment which of the two you found and why you chose what you chose.

## What to build

New directory `ios/Sources/TankbookCore/Config/`:

1. **`ConfigCanonicalizer.swift`** – `canonicalize(_ documentBytes: Data) throws -> Data`, implementing
   rules 1–6 over the served bytes. Reject depth > 64 and malformed JSON with a typed error.
2. **`ConfigSignatureVerifier.swift`** – verifies a base64 Ed25519 signature against the canonical bytes
   using a 32-byte raw public key. Injected key, not a global: `init(publicKey: Data)`. A malformed key,
   malformed base64, or wrong-length signature returns `false` – **never throws past the call site and
   never crashes**. A tampered cache must degrade to bundled defaults, not kill the app.
3. **`ConfigDocument.swift`** – a typed decode of the known fields, per
   `backend/src/Tankbook.Api/Config/config.schema.json` (read it for the exact shape and required keys):
   `version`, `issuedAt`, `notAfter`, `tier2OnDeviceLLM`, `tier3CloudFallback`, `llmQuota`,
   `ocrConfidenceThreshold`, `minSchemaVersion`, `referencePacks`, `rolloutSalt`, optional `apiBaseUrl`,
   `maintenance`, `flags`. **Unknown keys must survive** – keep the raw bytes alongside the typed view,
   because the cache stores the document verbatim and a future build must read keys this one does not know.
   Typed fields, never string-key lookup.

Conventions: Swift 6 strict concurrency, `Sendable` where it applies, no force-unwraps, SwiftLint clean.
Match the style of `ios/Sources/TankbookCore/Sync/` and `.../Logging/`. Must build and test on **macOS**
with no simulator – `swift test` is the gate.

## Tests (in `ios/Tests/TankbookCoreTests/`)

Use swift-testing (`@Test`, `#expect`), as the existing 108 tests do. You will need to add the fixtures
directory as a test resource in `ios/Package.swift` (`resources: [.copy("Fixtures")]` on the test target)
– check whether the existing fixture corpus already does this before adding a duplicate.

1. **Parity (the important one):** canonicalize `Fixtures/config/parity.document.json`; assert the output
   equals `Fixtures/config/parity.canonical.json` **byte for byte** (788 bytes, no trailing newline).
   That expected file was produced by the real C# canonicalizer.
2. **Signature accept:** verify `parity.signature.b64` against those canonical bytes with
   `parity.publickey.b64`. Expect `true`.
3. **Tampered document:** flip one byte of the document → verification fails.
4. **Tampered signature:** flip one byte of the signature → verification fails.
5. **Wrong key:** a different valid public key → verification fails.
6. **Number-token preservation, asserted directly:** a document containing `1e3`, `0.75`, `1.0`, `-0`,
   and `9007199254740993` canonicalizes with each token byte-identical to its source. Assert on the
   bytes, not on a parsed value – a test that parses both sides proves nothing.
7. **Key ordering:** nested objects with keys out of order sort ordinally at every level.
8. **Non-ASCII:** Cyrillic text is emitted raw, not `\u`-escaped.
9. **Escapes:** a string containing `"`, `\`, and control characters ``/`` round-trips to the
   minimal escape form.
10. **Malformed input:** truncated JSON, a non-object root, and depth > 64 each throw the typed error
    rather than crashing.
11. **Unknown keys survive** a decode → re-read of the raw document.

`#expect(true)`, asserting only that a call did not throw, or "tamper" tests that mutate a byte the code
never reads all count as not having done the task. The tests are re-run independently outside your run.
