## What to build

All in `ios/Sources/TankbookCore/Config/`.

### 1. Bundled defaults – `Config.default.json`
A complete, always-valid document: every field `ConfigDocument` requires. Ships as a package resource –
add a `resources:` entry for it on the **`TankbookCore` target** in `ios/Package.swift` (do not disturb
the test target's existing `exclude: ["Fixtures"]`). The bundled layer is **not signed** and is never
signature-checked: it is compiled into the binary, which is the root of trust. Say so in a comment.

### 2. Atomic cache file
`Application Support/Tankbook/config.cache.json`, shape per CONFIG.md:
`{ document, signature, etag, fetchedAt, activeBaseURL, consecutiveFailures }`.

- Store the **raw document verbatim** (`ConfigDocument.rawBytes`) – never re-encoded. The signature only
  verifies over the served bytes, and a future build must be able to read keys this one does not know.
- **Atomic write**: temp file then `FileManager.replaceItemAt` / rename. A crash mid-write must never
  leave a truncated document.
- File protection `.completeUntilFirstUserAuthentication`; `isExcludedFromBackup = true` (this removes
  the backup-tamper vector outright rather than merely defeating it).
- **Must be readable before GRDB opens** and must survive a failed database migration: **no GRDB
  dependency anywhere in this path.**
- **Inject the directory URL.** Tests must write to a temp directory inside the repo, never the real
  Application Support.
- File-protection and backup-exclusion APIs are iOS-only. Guard with `#if os(iOS)` so the package still
  builds and tests on **macOS**, and keep the surrounding logic testable on both.

### 3. Three-layer resolver
Precedence: Debug override (DEBUG builds only, compiled out of Release) > Remote (live, else cached) >
Bundled. Two rules operate at two levels and **conflating them is the classic bug** – get both right:

- **Document level: all or nothing.** Malformed, unsigned, badly signed, expired, below the Keychain
  floor, or older `version` than held → reject the **entire** document, fall through to the layer
  beneath. Never partially applied.
- **Key level: sparse override.** Once a document is valid, each key it *contains* overrides the layer
  beneath, per key. A document setting only `tier3CloudFallback` changes exactly that and nothing else.
  Note `ConfigDocument` decodes *all* known fields, so you need to know which keys were **present in the
  raw JSON** to implement sparse override correctly – decide how (inspect `rawBytes`), and test it.
- Unknown keys: ignored for resolution, **retained in the cache**.

### 4. `AppConfig` + `ConfigStore`
Shapes given in CONFIG.md → "How code consumes it". `AppConfig` is a `Sendable`, `Equatable` value type.
`ConfigStore` exposes `current`, `snapshot()`, `isEnabled(_:)`, `refresh()`.

- **Snapshot at the start of an operation**, used throughout. A capture flow must not observe
  `tier3CloudFallback` flipping halfway through.
- **Typed fields, not string keys.** Add a coverage test asserting every remote-configurable key listed
  in CONFIG.md → "What may be configured remotely" maps to an `AppConfig` field.
- **Injected, not a singleton.** Inject the cache directory, the **clock**, the verifier, and the
  Keychain. A hard-coded `Date()` is a defect: expiry and floor tests need a controllable clock.
- `isEnabled(_:)` applies rollout percentage via `rolloutSalt` + a device hash. Make the device
  identifier injected too, and test that the same salt+device is **stable across calls** and that 0% and
  100% behave exactly.

### 5. Ed25519 verification ON EVERY CACHE READ
Not only on fetch. Validating at fetch then trusting the cache bypasses signing entirely. Verify on every
read **including the read on cold start**, by calling `ConfigSignatureVerifier`.

### 6. Keychain rollback floor
Highest-seen `version`, stored with `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly` (therefore absent
from backups and unaffected by container tampering). Refuse any document below the floor. **A fresh
install has no floor, and that is correct** – do not invent one.

The real Keychain is unavailable in a plain `swift test` process on macOS. Put it behind a **protocol**
with an in-memory test double, keep the real implementation thin, and do not pretend the unit tests
exercise the real Keychain – say plainly in your report that they do not.

### 7. Document expiry
`issuedAt` / `notAfter` are already decoded. An expired cached document is discarded in favour of bundled
defaults, so an attacker cannot pin a device to a stale-but-validly-signed config forever. Uses the
injected clock.

### 8. Logging (`docs/LOGGING.md`)
Config is our data, not the user's → Safe class. Emit `config.apply` (version, changed keys **by name**,
source: live/cache/bundled) and `config.reject` (reason). Log the version and changed key *names*, never
the document body. Add `LogEvent` conformers next to the existing ones in
`ios/Sources/TankbookCore/Logging/LogEvents.swift`, matching their style. **CLAUDE.md rule 12 is
absolute: never log domain values.**

## Tests (`ios/Tests/TankbookCoreTests/`) – these ARE the acceptance criteria

swift-testing (`@Test`, `#expect`), matching the existing suite. Current count is **148 and must rise**.

1. **Bootstrap**: no cache, no network → resolves bundled defaults and is fully usable.
2. **Tampered document rejected ON READ** → falls back to bundled defaults. Tamper a field the code
   actually reads, and assert the store's resolved value is the bundled one.
3. **Tampered signature rejected on read** → bundled defaults.
4. **Version below the Keychain floor rejected**, even though validly signed.
5. **Cache deleted, old validly-signed document presented** → rejected by the floor.
6. **Fresh install (no floor) accepts a valid document** – the negative control for 4 and 5.
7. **Expired document** (`notAfter` in the past per the injected clock) → rejected, bundled used.
8. **The server's transient empty-signature baseline** (migration 003 seeds config v1 with an empty
   signature placeholder, signed at startup by `ConfigBaselineSeeder`) → rejected. Read the migration for
   the exact placeholder rather than guessing.
9. **Unknown key**: ignored for resolution, **retained in the cache bytes**, rest of the document applies.
10. **Sparse override**: a valid document setting only `tier3CloudFallback` leaves every other resolved
    value at its bundled value.
11. **Truncated / corrupt cache file** → falls back cleanly, no crash.
12. **Atomic write**: after a write, the cache parses; a partial temp file never becomes the live cache.
13. **Snapshot semantics**: a `snapshot()` taken before a refresh is unaffected by the refresh.
14. **Rollout**: same salt + device is stable across calls; 0% disabled, 100% enabled.
15. **Key coverage**: every remote-configurable key in CONFIG.md maps to an `AppConfig` field.
16. **Cold-start read verifies the signature** – assert verification happens on the cache-read path, not
    only after a fetch.

`#expect(true)`, asserting only that a call did not throw, or "tamper" tests that mutate a field the code
never reads all count as not having done the task. The tests are re-run independently outside your run.
