## What to build

### 1. A hardcoded-string detector
Something that fails when a SwiftUI view presents a **literal** user-facing string instead of a
catalogue key. It must run in CI and locally.

Design notes, because the naive version is worse than useless:

- **False positives will get it disabled.** `accessibilityIdentifier("homeEntryAmount")`, log messages,
  `#if DEBUG` launch-argument names, `Image(systemName:)`, and every string in `Tests/` and `UITests/`
  are **not** user-facing. If the check cries wolf on those, someone will delete it within a week.
- **Prefer a real signal over a clever regex.** SwiftUI's `Text("literal")` initialiser takes a
  `LocalizedStringKey`, so a bare literal *is* looked up in the catalogue – the failure is a **missing
  key**, not the literal itself. Consider driving the check off the catalogue: extract the keys the code
  references, compare against `Localizable.xcstrings`, and fail on a referenced key that has no entry, or
  an entry missing `ru`. That catches the real defect (a string that will not translate) rather than a
  style pattern.
- Whatever you choose, **write down in a comment what it does and does not catch.** A gate whose blind
  spots are undocumented gives false confidence.

### 2. The deliberate-failure test
`docs/TASKS.md` demands the build **fail on a deliberately hardcoded string**. Prove it, do not assert it:
a script or test that introduces a violation in a temporary copy, runs the check, and asserts it fails –
then cleans up. A gate nobody has seen fail has never been shown to work.

### 3. Sample keys resolve in both languages
A test that loads a handful of real keys and asserts both the EN and RU values are present and non-empty.
Include at least one **plural** key (Russian has three forms) and one **composed** key (`"%@ …"`), since
those are where the two languages diverge and where this project has already shipped bugs.

### 4. Wire it into CI
Add the step to `.github/workflows/ios.yml`, keeping every existing step working. It should fail the
build, not warn.

### 5. Coverage report
Print a short summary – key count, RU coverage, any key missing a translation – so a regression is
visible in the log rather than only as a red X.
