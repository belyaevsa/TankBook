## What to build

### 1. `project.yml` (repo root)
An XcodeGen spec producing:
- **`Tankbook`** – iOS application target, deployment target 18.0, sources under `ios/App/Sources`,
  depending on the local `TankbookCore` package.
- **`TankbookUITests`** – UI-testing bundle, sources under `ios/App/UITests`.
- A shared scheme named `Tankbook` so `xcodebuild -scheme Tankbook` works.

Add `Tankbook.xcodeproj/` to `.gitignore` (the file already exists; append, do not rewrite it).

### 2. App sources – `ios/App/Sources/`
- The `@main` App entry point.
- **Three tab roots, per SCREENMAP "Navigation conventions" rule 1: Log/Home, Trends, Garage.**
  Switching tabs **preserves each tab's own navigation stack** – that is a stated requirement, not an
  implementation detail, so each tab owns its own `NavigationStack` path.
- Navigation plumbing for the three navigation kinds, each with the behaviour SCREENMAP specifies:
  - **Tab roots**: no back button.
  - **Pushed screens**: back chevron + edge-swipe; back never discards saved data.
  - **Sheets**: drag handle, swipe-to-dismiss, plus an explicit close. Build the *mechanism* for "a sheet
    with unsaved typed input asks before discarding, a sheet with only scanned data discards silently" –
    a reusable modifier or wrapper. Do not build the individual sheets.
- **Placeholder destinations** for the screens P1.2–P1.11 will fill in, wired into the graph so the
  routes exist and are navigable. A placeholder is a named view with a title, nothing more.
- A typed route enum (or equivalent) so a later task adds a screen by filling a case, not by rewiring.

### 3. Theme wiring
The generated `ios/Sources/TankbookCore/Design/Theme.generated.swift` is the **only** sanctioned source
of colour. Wire it so the shell (tab bar, backgrounds, chrome) uses those tokens. **Any literal hex in UI
code is a lint error** – SwiftLint enforces this with a custom rule, and it is CLAUDE.md hard rule 5.

### 4. String Catalog
Create the app's String Catalog (`.xcstrings`) with **EN and RU** and put the tab titles in it. Every
user-facing string you introduce goes through it – hard rule 10, no hardcoded text.
**Scope note:** the pseudo-localization CI step is task **P0.3**, not yours. Create the catalogue and use
it; do not build the CI localisation gate.

### 5. CI
Update `.github/workflows/ios.yml` so the app target is actually built: install XcodeGen, run
`xcodegen generate`, and build the app scheme for a simulator destination. Keep the existing package
build, test and lint steps working – do not replace them.

## Tests

- **XCUITest** in `ios/App/UITests` that **walks every SCREENMAP edge that exists so far** and asserts

  forward exit. SCREENMAP's rule zero is "no dead ends" and the audit at the bottom of that file is what
  you are making executable.
