## What to build

### 1. Every catalog- or locale-derived value, editable
Name, make/model/year, plate, powertrain, fuel kinds, tank capacity, battery size, home currency, units,
`initialOdometer`, `paceLimitKmPerDay`, photo. **If Add car can set it, this screen can change it.**

Two consequences worth stating explicitly:
- **Editing `tankCapacityL` changes real maths** – partial-fill adjustment (P1.9) and the
  volume-vs-capacity warning on Confirm. A full-vehicle recompute follows the save (hard rule 2).
- **A user's edit is permanent.** No catalog pack update may later overwrite it (`SYNC.md` → Reference
  data), and a stale device must not revert it (S9, field-level merge). You are not implementing sync
  here, but do not write anything that would make those guarantees false.

### 2. Archive / unarchive (J13)
Archiving keeps history and removes the car from active stats. This is where the car switcher's
"Archive a car" lands.

**Add `Vehicle.archivedAt: Date?`.** P1.11 found the gap: the switcher wants to say *"Archived · sold Mar
2026 · history kept"* per `CarSwitcher.dc.html`, but there is no date field, so it honestly renders only
*"Archived · history kept"* rather than fabricating one. Adding the field is a schema change with a known
ripple – do all of it:

- `docs/SCHEMA.md` → the `Vehicle` block, with a sentence on why it exists.
- `ios/Sources/TankbookCore/Domain/Entities.swift` → the field + the public init.
- `ios/Sources/TankbookCore/Persistence/Migrations.swift` → the column (added to `v1`; nothing has
  shipped, so there is no field database to migrate – follow the `initialOdometer` precedent and its
  comment).
- `ios/Sources/TankbookCore/Persistence/Records.swift` → encode + decode.
- `scripts/generate-payload-schemas.swift` → the property, then **re-run the generator** so
  `docs/schemas/v1/vehicle.schema.json` regenerates.
- `docs/fixtures/payloads/v1/vehicle.json` → exercise it.
- Then **run the backend tests** (`cd backend && dotnet test`): the server embeds
  `docs/schemas/v1/*.schema.json` at build time, so the contract change must stay green there too.

`archived: Bool` stays as the flag; `archivedAt` is the *when*. Set it on archive, clear on unarchive.
Then update the switcher's row to use it.

### 3. Delete a car
The destructive path: a **system confirmation** (the one place red lives), cascading to the car's entries
as tombstones so Recently deleted can restore them – nothing lost silently (hard rule 8).

### 4. The header
`docs/DESIGN.md`: **one row** – title and actions on the same line, not a stacked large title with a
toolbar above it. Match how the other detail screens already do it.

## Tests

**L1 (`ios/Tests/TankbookCoreTests/`, macOS, no simulator)**:
- **Every catalog-derived field round-trips an edit** through the repository.
- **Editing `tankCapacityL` changes partial-fill maths**: a segment that used the old capacity produces a
  different adjusted litres afterwards. Assert the number.
- **A recompute follows a vehicle edit** – the headline reflects the new units/capacity.
- **`archivedAt` set on archive, cleared on unarchive**, and `archived` stays consistent with it.
- **An archived car keeps its history** and stays out of active stats (J13).
- **Deleting a car tombstones its entries** and Recently deleted can restore them.
- **Override permanence**: a user-edited `tankCapacityL` is unchanged after applying a catalog pack that
  carries a different value for that model. This is hard rule 13 made executable – write it even though
  the pack updater is P5.7, using the catalog data directly.
- The payload fixture with `archivedAt` validates against the regenerated schema.

**L4 (`ios/App/UITests/`)**:
- Every catalog-derived field is reachable and editable.
- Archiving from here updates the car switcher's row.
- Delete raises the system confirmation; cancelling leaves the car intact.
