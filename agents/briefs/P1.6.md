## What to build

### 1. The Edit entry screen
The entry's fields, editable, per the artboard. A `FillUp` shows the same three-number card as
ConfirmManual; other entry types show their own fields. Every value is editable – hard rule 13.

### 2. Full-vehicle recompute – normative, quoted
From `docs/SCHEMA.md`:

> Any change to any FillUp of a vehicle (create, edit, delete, restore, sync-merge) triggers a **full
> recompute of that vehicle's segment list** – no surgical invalidation. […] Derived values live in
> memory only; recompute runs synchronously on save and after every sync merge batch.

**Do not attempt surgical invalidation.** The doc explains why and it is not a performance question: an
edit has non-local effects. Toggling `isFull` splits or merges segments; a date edit moves a fill into a
different segment; an odometer edit changes two segments because a full fill is a boundary. A linear pass
is sub-millisecond at realistic history sizes and is correct by construction.

Also normative, and easy to get wrong: **no re-firing of past events.** Anomaly `.attention` transitions
and reminder threshold notifications must never fire from a historical edit – that state re-evaluates
silently. A user correcting a typo from March must not be notified about March.

### 3. The delta toast
`docs/ERRORS.md`: *Edit shifts stats* → toast on save: **"Consumption updated: 6.9 → 6.8 L/100km"**,
informational, tapping it opens Trends.

- The toast appears **only when a figure actually changed**. An edit that moves nothing shows no toast –
  claiming an update that did not happen is worse than silence.
- Old and new both come from the engine, before and after. Never recompute one and estimate the other.

### 4. The four ERRORS.md states, copy verbatim
| Condition | Shows | Next step |

| Edit re-breaks cross-check or timeline | Same amber mechanics as Confirm | Same fixes; save-anyway keeps flag |

The S1 sync row is fixture-driven (no sync until P4) – say so in your report. **Delete is the only place
red is allowed** (hard rule 5): a system confirmation dialog. Deleting routes to Recently deleted with a
30-day window (P1.7 builds that screen; the tombstone write is yours).

### 5. Money edits clear the snapshot (hard rule 3)
Editing an amount **clears the rate snapshot** – the pair is re-derived, `rateDate` stays the entry date,
never "today". `docs/SCHEMA.md` Money is normative and there is an existing L1 suite for it; make sure the
edit path obeys the same rules rather than writing a second interpretation.
