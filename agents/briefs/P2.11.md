## The defect, with its fixture

`Spike/ReceiptSpike/fixtures/receipts/receipt-034-lukoil-m11-ekto95-contract-zero-price-ru.jpeg`
prints a product line that Vision reads as:

```
Plus (AИ-95-К5), л        <- the A is LATIN, the И is Cyrillic
```

The octane regex is Cyrillic `А[ИН]`, so it misses, and the fuel kind resolves to **nil**. Vision
picks glyphs **by shape, not by the document's language**, so this is not a one-off: the whole
confusable set applies - `А/A`, `О/O`, `Р/P`, `С/C`, `Е/E`, `Х/X`, `К/K`, `М/M`, `В/B`, `Н/H`,
`Т/T`.

## The constraint that makes this more than a `replace`

**Normalise for MATCHING only, never in stored text.** A station name must survive **as printed** -
if a receipt says `Circle K`, the entry stores `Circle K`, not a transliterated variant. So the
normalisation belongs inside the extractor's comparison path, and anything that reaches
`FuelExtraction.station` / vendor text must be the original characters.

That split is the load-bearing invariant, and it is what your mutation will be judged on.
