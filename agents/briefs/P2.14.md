## The bug, exactly

`ios/Sources/TankbookCore/Extraction/FuelExtractor.swift`:

```swift
private func modal(_ candidates: [Double], preferring primary: [Double]) -> Double? {
    guard !candidates.isEmpty else { return nil }
    let counts = Dictionary(grouping: candidates, by: { $0 }).mapValues(\.count)
    let maxCount = counts.values.max() ?? 0
    let modes = counts.filter { $0.value == maxCount }.map(\.key)
    if modes.count == 1 { return modes[0] }
    // Tie: prefer the value that the primary labels (ИТОГ/ИТОГО/...) named.
    let primaryCounts = Dictionary(grouping: primary, by: { $0 }).mapValues(\.count)
    return modes.max(by: { (primaryCounts[$0] ?? 0) < (primaryCounts[$1] ?? 0) }) ?? modes.first
}
```

**Three order dependencies, not one.** `Dictionary` iteration order is not guaranteed in Swift, so
`modes` comes out in an arbitrary order; `max(by:)` over elements with **equal** `primaryCounts`
returns whichever that order left last; and `?? modes.first` is order-dependent too. When two total
candidates tie on count **and** on primary-label count, the answer is whatever the hash seed
decided.

**Found by P4.13**, which required three sweeps per image and watched the receipt score flip
between **29/96 and 30/96** across identical runs - `receipt-021`, `receipt-026`, `receipt-029`.

## Why this is more than a parser bug

`Spike/ReceiptSpike/fixtures/high-water.json` and `PumpPhotoGate.measuredHits` are **gates asserted
against a live score**. `AccuracyRatchetTests.pumpModeShipsOffWhileTheCorpusIsBelowTheGate` asserts
`scored.hits == PumpPhotoGate.measuredHits` as an **equality**. A tie-break that moves therefore
makes **CI itself intermittently red**.

It also **blocks a stale gate from being tightened**: receipts records **45/93** while measuring
**46/96** live (the mark predates `receipt-035`). That was deliberately not raised, and
`high-water.json`'s own note says why - pinning a gate to a number that is not reproducible is the
same failure class as a log sweep that matches a timestamp. **Raising it is part of this task.**

## Choose the tie-break deliberately, and say which

**Do not merely stabilise it.** Sorting for determinism and moving on would leave an arbitrary rule
that nobody chose. State the rule and defend it.

**The strongest candidate is to return `nil`**, and the precedent is in this very file:

- a printed `0.00` becomes `nil` because *"a zero means the price is not on this receipt, never
  that the fuel was free"*;
- an unmarked operand pair returns `nil` rather than guessing which number is the price
  (`SCHEMA.md` -> Fuel price bands, step 5: *"Undecided. Leave the fields empty and let the user
  type them. An empty field the user fills is a far better outcome than a confident wrong one."*);
- hard rule 13: a confident wrong value is worse than an empty field.

An unbreakable tie between two totals is, precisely, not knowing the total.

**If refusing lowers the score, that is information, not failure.** Report the delta honestly. If
you conclude a different rule is better, argue it from the corpus - but the rule must be **named in
the code and asserted by name in a test**, not implied by a sort.

## Tests

Count now: `swift test` **635**. Run it first, record the real number, and it must rise.

1. **Determinism across PROCESSES, not calls.** A fixture whose totals tie on both counts must
   return the **same** answer over **100 separate process runs**. **Swift's hash seed is fixed
   within one process**, so calling the function twice in one test agrees even while the bug is
   live - that assertion would prove nothing. Drive it by running the binary repeatedly (or set
   `SWIFT_DETERMINISTIC_HASHING=0` explicitly across runs) and assert every result identical.
2. **The chosen rule asserted by name**: if the answer is `nil`, assert `nil` for a constructed
   double-tie; do not assert merely "the same value each time".
3. **`receipt-021`, `receipt-026`, `receipt-029`** each asserted individually - they are the three
   that flipped.
4. **A single clear mode is unaffected** - the common path must not change.
5. **A tie broken by the primary label still resolves** to the primary-labelled value; only the
   *unbreakable* tie changes behaviour.
6. **The ratchet passes repeatedly**: run `AccuracyRatchetTests` several times and confirm the live
   equality assertion holds every time.

### Vacuous-assertion traps for this task

- **Calling the function twice in one process and calling that determinism.** One process shares a
  hash seed; that test passes today, with the bug live. This is the trap the whole task turns on.
- Asserting "a value is returned" rather than **which** value.
- Fixing `modes.max(by:)` and leaving `?? modes.first` order-dependent.
- Raising `high-water.json` to a number you observed once.
- Putting LLM-arm numbers into `high-water.json`.
