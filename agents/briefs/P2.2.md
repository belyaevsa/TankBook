### 2. Fix the failures the corpus documents

These are the measured defects. Each names its fixture. Fix as many as you can and **report
honestly which you did not**.

- **The total-finder grabs the wrong line.** It returns VAT on `receipt-002` (3555.89) and
  `receipt-011` (700.28), the `ОКРУГЛЕНИЕ` line on `receipt-012` (0.08), and a mixed
  receipt's grand total on `receipt-009` (6264.00 when the fuel line is 6135.24).
  **The reading-order bug:** in a right-aligned two-column receipt Vision emits *value before
  label*, because it sorts by vertical position and the value sits higher or is a separate
  observation. A finder that looks for a number *after* its label lands on the next row's
  value. Use the **bounding boxes** to pair a label with the value on its own baseline, rather
  than relying on array order.
- **Volume and unit price come back swapped** (`receipt-007`: 99.4 L at 43.61 instead of
  43.61 L at 99.40; `receipt-008` likewise). Both report cross-check ✓ because `a*b == b*a`.
  Implement the ladder from `SCHEMA.md`: labelled column → unit-marker position (`л`/`L`/`gal`
  attached to an operand) → the user's price history → a curated band → **undecided**.
  In this task, implement steps 1, 2 and 5, and define the interface for 3 and 4 with an
  injected provider; the pack itself is P5. **When undecided, return nil for those fields.**
  A nil the user fills is correct behaviour; a confident wrong value is the defect.
- **A station number is read as the fuel grade.** `receipt-015` returns 98 for an АИ-95
  fill, taken from `ООО"КЕДР" АЗС-98` on line one. A bare `92|95|98|100` match also hits
  pump numbers (`ТРК №3`), reservoir numbers and addresses. Anchor the grade to the product
  line.
- **Repeated values are free redundancy.** `receipt-015` had one of its three printed totals
  misread as `=5380.0D` at confidence 1.00, and it did not matter because the other two read
  cleanly. Take the **modal value across repeated occurrences**, not the first match - it
  costs nothing and defeats the single-digit misread no confidence threshold can catch.
  `receipt-016` benefits twice over: it prints `1 932.00` with a space thousands separator in
  one place and `1932.00` in another.
- **Fuel kind is not normalised.** The parser emits raw `100`, `95`, `АИ-92`, `ДТ`, `98`. Map
  to the `docs/SCHEMA.md` FuelKind vocabulary. `ДТ`/`Диз.топл.`/`ДТ-Л-К5`/`АТ-Л-К5` → diesel,
  `АИ-92-К5` → petrol92, `СУГ` → LPG, etc. **On a pump display, do not attempt fuel kind at
  all** – the grade labels there belong to every nozzle, not the fill (documented finding).
- **Mixed receipts** (`receipt-009`): the fuel amount is the **fuel line**, never the grand
  total (hard rule 4). Detect and return the fuel line. Note the adversarial detail: on that
  fixture the bottled water costs `129.00`, the **same number** as the fuel's price per litre.
- **Rounding lines.** `ОКРУГЛЕНИЕ` / "your discount" mean the printed extension and the total
  legitimately differ by under a currency unit. Do not treat that as a parse failure, and do
  not let the rounding line be mistaken for the total.

### Vacuous-assertion traps for this task

- `#expect(true)`, or asserting only that parsing did not throw.
- Asserting `liters * price == total` – that is exactly the check that **cannot** see a swap.
  Assert the fields individually.
- Editing `expected.csv` so a test passes.
- Recording a high-water mark **below** what the code actually scores, so the ratchet can
  never fire.
- Testing only the fixtures you fixed and dropping the ones you did not, so the class average
  rises by shrinking the corpus. The file count per class must not go down.
