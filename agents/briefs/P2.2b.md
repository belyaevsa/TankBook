## The rule this task exists to honour

`CLAUDE.md` hard rule 3 (**money is a pair**) and `docs/SCHEMA.md`, which types money as
`Decimal` and volume as `Double`, verbatim:

```swift
FillUp: EntryCommon {
  volumeL: Double               // always stored in liters; displayed in vehicle unit
  unitPrice: Decimal?           // per liter, original currency
```
```swift
  amount: Decimal; currency: CurrencyCode          // as paid: 289.50 PLN
```

`FuelExtraction` types `unitPrice` and `total` as `Double?`. `4201.68` does not survive a binary
float round-trip, so a value read correctly off a receipt can be stored wrong. P2.3 and P2.5 both
convert at their own boundary rather than propagate the `Double`, which contains the damage – but
the root type is still wrong, and every new consumer has to remember the workaround.

### Vacuous-assertion traps for this task

- `#expect(true)`, or asserting only that a call did not throw.
- Comparing two `Decimal`s that were both produced by the same `Double` conversion – they will
  agree, and prove nothing. The reference value must be written as a **literal** in the test
  (`Decimal(string: "4201.68")!`), not derived from a `Double`.
- Asserting `abs(a - b) < 0.005` on the round-trip test. A tolerance hides exactly the defect
  this task fixes; that test must assert **equality**.
- Changing `expected.csv` or `high-water.json` to make something pass.
