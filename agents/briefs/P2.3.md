## The two rules this screen must not break

**Hard rule 15 - two doors.** Manual entry and capture are peer paths. A user who typed and a
user who scanned must end up in **the identical sheet**, editing the same fields. Concretely:
an extraction with every field nil must render as an ordinary empty form - **not** an error, not
a warning, not a "scan failed" banner. It is simply the manual form with nothing pre-filled.

**Hard rule 13 - the app suggests, the user decides.** Every pre-filled value is a default
input, editable at the moment it is offered and again afterwards. Dimming a low-confidence
field must never make it harder to edit, harder to focus, or visually read-only.

## What to build

### 1. Pre-fill from an extraction
`ConfirmManual` gains an optional `FuelExtraction` input. Present fields fill; **nil fields
stay blank and focusable**. A nil must never render as `0` or `0.00` - a zero is a wrong fact,
a blank is an honest absence.

### 2. Confidence dimming, and the threshold that gates it
Per-field visual treatment for a low-confidence extraction, per the artboard. Two hard
constraints:

- **Dimmed ≠ disabled.** A dimmed field is fully editable, focusable and announced normally to
  VoiceOver. Assert this in a test.
- **The threshold is L1-testable and must not be Vision's confidence score.** `pump-004`
  proved Vision returns a **wrong digit at confidence 1.00**, so a raw confidence gate is
  worthless. Drive dimming off whether the *extraction* resolved a field and whether the
  cross-check agrees - not off an OCR score. Put the thresholds in one named place with unit
  tests.

### 3. Tap-to-verify crops
Tapping a pre-filled field shows the crop of the source image that value came from, so the
user can check it without leaving the sheet. `FuelExtraction` does not carry crops today -
**define the seam** (a small `CGRect` + image reference passed alongside), render it when
present, and degrade to no-op when absent. Do not add Vision to get them.

### 4. Cross-check lock
Extend the existing check line: `✓` when `liters x unitPrice ~= total` within CHECK 3's
tolerance `max(0.02, amount x 0.005)`, amber mismatch otherwise, both already partly built.

**Write this comment where the lock is computed, because it is the trap:** a green cross-check
proves the three numbers are *consistent*, never that litres and price are the *right way
round* - `a x b == b x a`. The corpus has two fixtures where the parser swapped them and the
check still passed. So the lock must never be used to suppress editing or to skip confirmation.

### 5. The QR anchor wins on total
When a `FiscalQRAnchor` is present, its total is **exact** and outranks the OCR total. On
`.disagrees`, the QR value fills the field. On `.suggestsMixedReceipt`, the **fuel line
stands** (hard rule 4) and the difference is left for P2.4 - do not build the "Also on this
receipt" UI here.

### 6. Motion, and the reduced-motion variant
The lock animation is J3's emotional beat - keep it small. **Honour
`accessibilityReduceMotion`**: a variant with no animation that still communicates the state
change. Required by `docs/DESIGN.md`'s accessibility floor and by the task's checks.

### Vacuous-assertion traps
`#expect(true)`; asserting a view exists without asserting its text or value; testing dimming by
reading the flag you just set rather than the rendered field; a "swapped" test that asserts the
product rather than the assignment; asserting an empty form shows *something* rather than
asserting it shows **no error**.
