## What is wrong today

Confirm shows a `95 / Diesel` chooser, because the seed car is `fuelKinds: [.petrol95, .diesel]` –
**a car that burns both, which does not exist.**

`docs/DESIGN.md` already makes fuel kind **conditional for display**: *"a diesel-only car printing
Diesel on every row is noise dressed as information"*. The same rule must govern **input**.

The distinctions that matter, and they are not symmetric:

- Petrol grades (92/95/98/100) **share a tank** and are a real driver's choice.
- **LPG/CNG/E85 alongside petrol are real** – bi-fuel and flex-fuel cars exist.
- **Diesel with petrol is not.**

## What to build

1. The Fuel row offers exactly `vehicle.fuelKinds` – never a kind the car cannot burn.
2. With a **single** kind it is a static value, not a chooser – **but it stays correctable**.
   Hard rule 13 is explicit: a screen that pre-fills a value it will not let the user change is a
   bug, and so is one that only lets them change it once. Decide how a single-kind car's value is
   corrected and say so in your report.
3. `AddVehicle` rejects diesel + petrol while allowing petrol + LPG/CNG/E85.
4. The seeds stop describing impossible cars. `fuelKinds: [.petrol95, .diesel]` currently appears
   in at least: `ios/App/Sources/Home/HomeTestSeed.swift:261`,
   `ios/App/Sources/TankLevel/TankLevelView.swift:409`,
   `ios/App/Sources/RecentlyDeleted/RecentlyDeletedTestSeed.swift:63`,
   `ios/App/Sources/ConfirmManual/ManualFillUpTestSeed.swift:21`,
   `ios/App/Sources/CarSwitcher/CarSwitcherTestSeed.swift:44`.
   **Verify that list yourself before relying on it** – task rows in this repo have carried wrong
   file lists and wrong counts four separate times. Changing a seed car changes what several UI
   suites see, which is why the Checks below name more suites than you might expect.

**`fuelGrade` is a separate field and still varies for a diesel car** – the corpus has
`ДТ-Е-К5 Танеко` and `АТ-Л-К5 Ультра`. Do not collapse grade into kind.

## Named vacuous traps for this task

- A test that asserts the chooser has "the right count" of options without asserting **which**.
- Asserting a diesel car is not offered petrol, without the converse (a petrol car not offered
  diesel) – a filter inverted the wrong way passes one and fails the other.
- Testing the rule only on the seed car. Cover a **single-kind** car, a **petrol 92+95** car, and a
  **petrol + LPG** car; the interesting cases are the ones the seed does not contain.
- A single-kind test that asserts the chooser is gone but never asserts the value is still
  editable – that would ship a hard-rule-13 violation with a green test.
