## Why it is genuinely hard, so you do not rediscover it

From `Spike/ReceiptSpike/fixtures/pump/README.md` - read it in full before writing:

- **Decimal separators vanish.** `pump-003` lost every one: `208863 / 8525 / 2450` for
  `20886.3 / 85.25 / 245.0`, each needing a *different* divisor.
- **The cross-check cannot reconstruct scale.** `liters x price = total` is scale-invariant, so
  brute-forcing divisors gives **12** solutions for `pump-003`, not one. Adding a price band
  narrows it to 3 and a volume bound to 2 - a factor-of-ten ambiguity in VOLUME survives every
  automatic filter, and that is the worst error the app can make.
- **Confidence is not correctness.** `pump-004`: Vision returned a wrong digit at **1.00**. No
  threshold can catch that, so `ocrConfidenceThreshold` cannot gate this mode.
- **Four prices, one fill.** `pump-005` shows four grade prices and does not say which was
  dispensed; the right one is last, so position does not help. `pump-007` at least labels it.
- **The surround is arbitrary.** `pump-008`'s display *is* a video screen with a cartoon
  playing behind the numbers. `pump-001` returned `0.700` litres from a sandwich advert.
- **A pump prints each number once**, so the modal-value redundancy that rescues receipts
  (`receipt-015`, `receipt-016`) is unavailable.

## What to build

### 1. The flag, defaulting OFF and not remotely flippable into truth
A feature flag gating pump-photo mode. It must default **off**, and it must **not** be possible
for a remote config document to turn it on while the corpus gate is failing - the gate is a
property of the build's own measured accuracy, not a runtime opinion. Read
`docs/CONFIG.md` → "Config can never disable a security control" for the shape of that argument;
the same reasoning applies to an accuracy gate.

### 2. The gate, wired to the ratchet
The existing L5 ratchet (`ios/Tests/TankbookCoreTests/AccuracyRatchetTests.swift` +
`Spike/ReceiptSpike/fixtures/high-water.json`) already scores the `pump` class. Add a test that
**fails if the flag is on while pump accuracy is below 95%**, and passes with the flag off. That
single test is the deliverable: it makes "the gate IS the check" executable rather than a note.

### 3. The capture path, honestly degraded
Pump mode being off must not mean a dead end (hard rule 15 - two doors, always). With the flag
off, a user pointing the camera at a pump gets the ordinary manual form, pre-filled with nothing,
and no message implying failure. **Do not add an error state**; there is no error - the feature
simply is not offered.

If the flag is on (developer builds), the extraction may run and pre-fill, but every field it
produces is a default input the user edits (hard rule 13), and **volume in particular must never
be written without the user seeing it** - the factor-of-ten ambiguity above is invisible on a
Confirm screen and corrupts consumption silently.
