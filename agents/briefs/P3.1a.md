## What to build

1. **`ios/App/Sources/ServiceEntry/`** – a new folder with the screen, its form state and its
   sections, mirroring how `ConfirmManual/` is organised.
2. **Line items.** Add, edit, delete rows of `title` + `category` + `cost`. The category chooser
   offers the `ServiceCategory` cases; `.other(String)` takes free text and **must not lose that
   text** when the record round-trips through persistence.
3. **The lump-sum path is first-class, not a degraded one.** A record with exactly one
   uncategorized item carrying the whole total saves and reads back correctly, and **nothing in
   the UI pushes the user to itemize** - no warning, no badge, no disabled Save.
4. **The odometer rule.** Pre-filled from the last known value for the vehicle and editable.
   Required **only** when a line item sets a km lifetime or a tire set is mounted; otherwise a
   blank odometer saves without complaint. When it is required and blank, the message names its
   next step (hard rule 7).
5. **Date row.** Defaults to today, editable. The artboard's "· invoice" provenance caption
   belongs to P3.1b - render the row so a provenance caption can appear later without relayout.
6. **Save** writes a `ServiceRecord` through the repository and returns to Home
   (`SCREENMAP.md`), and the entry appears in the Log stream.
7. **Strings.** Every one through the String Catalog, EN **and** RU. **Read the rule at the top
   of `ios/App/Sources/Localization/L10n.swift` before you write a single string** - four bugs
   have shipped where runtime data and copy shared one expression, because `Text(_: String)` does
   not localise and the gate cannot see it. Compose a **full localised phrase per language**;
   never concatenate.

### Vacuous-assertion traps for this task

- `#expect(true)`, or asserting only that a call did not throw.
- An odometer test that only checks the **not-required** side - the bug is a screen that demands
  an odometer it does not need, and that test would stay green through it.
- Asserting a line item was added by re-reading the same in-memory array the test just wrote,
  without going through the repository.
- Comparing money with `Double` equality or with a tolerance. Use `Decimal` literals
  (`Decimal(string: "148.00")!`).
- A "lump sum saves" test that constructs the record directly instead of driving the screen's
  form state - the thing under test is that **the UI does not force itemization**.
