## The rule this task exists to honour

`docs/SCHEMA.md` -> **"Reminder lifecycle (normative)"** is the authority, and it is quoted here
because the transitions are the whole task:

> **COMPLETE** -> prompt "log the cost?": creates a pre-filled ServiceRecord/Expense (category,
> title, current odometer) -> status = `.done(entryId)`. **Declining is fine: `.done(nil)` -
> completion never forces bookkeeping.** If recurrence is set, the NEXT occurrence is created as a
> NEW Reminder row, anchored at the **COMPLETION** date/odometer (not the original due - no
> drift), linked via `sourceEntryId`. Old rows stay as history.
>
> **RESCHEDULE** -> edits dueDate/dueOdometer in place; a fired `.attention` **resets so it can
> notify again**.
>
> **DELETE** -> tombstone (syncs like everything). **Distinct from `.dismissed`**, which keeps the
> row with a reason and feeds anomaly/insight logic ("dismissed: sold the tires").

Two more rules from the same file: `.attention` **is derived at read time from thresholds, but
the transition is stored** so notifications fire once rather than on every recompute; and a
reminder with **both** `dueDate` and `dueOdometer` is due on **whichever comes first**.

1. **The full transition table** (L1), which is this task's gate: every transition in the
   lifecycle block, as a table-driven test - scheduled/attention/done/dismissed crossed with
   complete/reschedule/delete. A transition the table does not cover is a transition that will
   break in P3.5.
2. **Completion anchors at completion, not at the due date** (L1). Complete a reminder **late**
   and assert the next occurrence is measured from the completion date/odometer. This is the
   "no drift" rule and the test that proves it must use a late completion - completing exactly on
   time cannot distinguish the two.
3. **Declining the cost prompt still completes** (L1): `.done(nil)` is a valid terminal state.
4. **Reschedule resets a fired `.attention`** (L1) so it can notify again.
5. **`.dismissed` is not delete** (L1): the row survives with its reason; a deleted reminder
   tombstones.
6. **Whichever-comes-first** (L1): date-first and odometer-first cases both resolve correctly.
7. **A reminder with neither due field refuses to save** and names its next step.
8. **L4**: the list renders both groups from a seed; the empty state renders; the form saves and
   returns to the list.

### Vacuous-assertion traps for this task

- `#expect(true)`, or asserting only that a call did not throw.
- A transition test that asserts the new status **without** asserting what the transition
  *created* (the next occurrence row) or *preserved* (the old row as history).
- Testing recurrence with an on-time completion - it cannot tell "anchored at completion" from
  "anchored at due", which is the bug.
- Asserting `.dismissed` by checking a boolean flag rather than that the row and its reason are
  still readable.
- Computing "in 12 days" in the test the same way the code does. Assert against a **literal**.
