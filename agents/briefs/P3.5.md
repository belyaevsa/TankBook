## What to build

1. **The ReminderComplete sheet**, per the artboard: what was completed, when, and at what
   odometer; the "Log the cost?" prompt with **Type amount** and **Skip – just mark done**; the
   next-cycle line when recurrence is set; and the secondary actions.
2. **The chain**: Type amount -> the existing ServiceEntry (or Expense entry for a non-service
   category) **pre-filled** with the reminder's category, title and the current odometer -> on
   save, the reminder becomes `.done(entryId)` carrying the **real** entry id.
3. **The decline path**: Skip -> `.done(nil)`. A valid terminal state; completion never forces
   bookkeeping. The next occurrence is still created if recurrence is set.
4. **The next cycle**, persisted: a NEW Reminder row anchored at the completion date/odometer,
   linked via `sourceEntryId`, with the old row left as history. Anchoring is the load-bearing
   part - "no drift".
5. **Strings** through the String Catalog, EN **and** RU. **Read the rule at the top of
   `ios/App/Sources/Localization/L10n.swift` first** - `Text(_: String)` does not localise, so an
   expression mixing runtime data and copy renders its English key while the gate stays green.
   Five bugs have shipped that way. "Completed today at 119 486 km" and "in 15 000 km or Aug 2027"
   are exactly that shape: a full localised phrase per language, never concatenation, and Russian
   needs plural rules.

## Tests

the real numbers, and both must rise.

1. **The chain, end to end** (L3-style, through a real in-memory repository): complete -> a
   pre-filled entry is saved -> the reminder is `.done(entryId)` with **that** entry's id -> the
   next occurrence exists as a **new row** and the old row survives as history.
2. **Anchored at completion, not at the due date** - complete a reminder **LATE** and assert the
   next occurrence is measured from the completion date/odometer. Completing on time cannot tell
   the two apart, which is why the test must be late.
3. **Decline still completes**: Skip yields `.done(nil)`, no entry is written, and the next
   occurrence is still created when recurrence is set.
4. **The pre-fill is editable** (hard rule 13): the category/title/odometer arrive as defaults and
   every one can be changed before saving.
5. **A non-recurring reminder produces no next occurrence** - the other half of rule 2.
6. **L4**: the sheet renders from a seed; Skip returns to the list with the row in history; Type
   amount lands in the entry screen with the pre-fill visible.
7. **Localization gate** exit 0, RU 100%.

### Vacuous-assertion traps for this task

- `#expect(true)`, or asserting only that a call did not throw.
- Testing the chain with an **on-time** completion - it cannot distinguish "anchored at
  completion" from "anchored at due", which is the bug.
- Asserting `.done` **without** asserting the entry id it carries, or asserting the next
  occurrence exists without asserting **what it is anchored to**.
- Building the expected next-due by calling the same function the code calls. Write the expected
  date/odometer as **literals**.
- A "decline" test that never checks that **no entry row** was written.
