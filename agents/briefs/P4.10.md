## The contract, verbatim from `docs/API.md`

```
POST /extract  - bearer
{ kind: "receipt" | "pump" | "chargeScreenshot" | "invoice",
  image: <base64 <= 4 MB>,
  hints: { currency?, locale?, vehicleFuelKinds? } }
-> { fields: { <FieldRef>: { value, confidence } }, pipeline }   // per SCHEMA.md ExtractionMeta
-> 402 when the tier lacks quota
-> 429 per-period quota spent
```

> Images processed **transiently - never stored**, per the signed-off stance.

> `402`/`429`: the client falls back to the on-device result (JOURNEYS F4) - **never an upsell
> mid-capture**.

**Hard rule 9 bounds the response**: the server returns **field values, never domain judgements**.
It does not decide mixedness, duplicates, or whether a fill is plausible. No endpoint reads what a
field *means*.

## What to build

1. **The provider seam**: an interface, a real implementation, and a scripted double. The suite
   must never make a paid call.
2. **`POST /extract`**: validate the envelope (**4 MB cap on the base64 image**, known `kind`),
   call the provider, map to `ExtractionMeta` with **per-field confidence**, and return.
3. **Quota from `llm_usage`**, per account per period: **`402`** when the tier lacks quota at all,
   **`429`** when the period's allowance is spent. Two different conditions, two different codes -
   do not collapse them.
4. **Meter what you spend**: increment `requests` and `tokens` for the period. A request that fails
   at the provider must not bill the user for a result they never got - state your rule and test it.
5. **Transient images**: the bytes exist only for the duration of the request. Nothing written to
   disk, blob storage, or a log line. **Assert this**, do not merely intend it.
6. **The response carries confidence, and the server never judges.** Return values and confidence;
   do not compute mixedness, duplicate-ness or plausibility (hard rule 9).
7. **A cross-check signal, not a verdict.** Where the model returns liters, unitPrice and total,
   the server **may** report whether they multiply out - but that is a *field-level signal for the
   client*, never a reason to alter or suppress a value. P4.12 proved the cross-check is blind to
   swaps and scale shifts, so it can never be used as a trust gate.

## Tests (L2, against real Postgres via Testcontainers)

Count now: `dotnet test` **202**. Run it first, record the real number, and it must rise.

1. **A 4 MB + 1 byte image is rejected** with the documented status, and the provider is **never
   called** - assert the double's call count is zero. A cap enforced after the call has already
   paid for it.
2. **`402` and `429` are distinct**: no-quota-at-all vs period-spent, each with its own trigger and
   its own status. A test that only exercises one passes an implementation that returns the same
   code for both.
3. **Quota is metered**: a successful call increments `requests` for the right `(account_id,
   period)`; assert the row, not the response.
4. **A provider failure does not bill the user** (or does, if you argue that is right - but state
   the rule and assert it either way).
5. **No image, base64 blob, or field value in any log line** (hard rule 12), swept through
   `WithoutMachineFields()`. Assert the *absence*, and include a field value that would be
   recognisable if it leaked.
6. **Nothing is persisted**: after a successful extract, no blob row, no file, no image column.
   Assert the absence.
7. **The response shape matches `ExtractionMeta`** with per-field confidence, including a
   low-confidence field surviving as a value plus a low number - **never dropped**. Dropping a
   low-confidence field would silently convert "uncertain" into "absent", which is a different
   claim.
8. **Cross-account isolation**: one account's quota cannot be spent by another.
9. **Any new migration applies and rolls back.**

### Vacuous-assertion traps for this task

- Asserting a status code without asserting the `llm_usage` row that should or should not have
  changed.
- Enforcing the size cap *after* calling the provider - the test must assert the provider was not
  called.
- Collapsing `402` and `429` into one path.
- A "nothing is stored" test that checks only that no blob row exists, and not the filesystem.
- Mocking the repository and asserting the mock. These are L2 tests against real Postgres.
- Testing the cross-check as if it were a trust gate. P4.12 proved it is blind to swaps; a test
  that expects it to catch one is asserting something false.
