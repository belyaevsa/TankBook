## The contract, verbatim from `docs/API.md` (the authority)

| Endpoint | Auth | Contract |
|---|---|---|
| `POST /blobs/begin` | bearer | `{ sha256, size, contentType }` -> `{ status: "exists" }` \| `{ status: "upload", url: <presigned PUT>, expiresAt }` \| `413` size cap (images 25 MB, PDFs 10 MB per `SYNC.md`) \| `429` quota. |
| `POST /blobs/commit` | bearer | `{ sha256 }` -> `204` after server verifies object + size. Referencing records must push only after commit. |
| `GET /blobs/{sha256}` | bearer | `302` -> short-lived presigned GET (~10 min, single object). `404` if not owned by this account. |

`docs/SYNC.md` -> "Attachments: the blob pipeline" adds what must hold:

> Layout: one private bucket, keys **`{account_id}/{sha256}`** - content-addressed, so identical
> files dedupe **per account** and a key never changes.

```
1. Client computes sha256 of the rendition.
2. POST /blobs/begin -> { status: exists } | { status: upload, url, expires: 15 min } | 413 | 429
3. Client PUTs the bytes directly to the presigned URL (resumable retry: just re-begin).
4. POST /blobs/commit { sha256 } -> server verifies object existence + size, inserts the blobs row.
5. Only THEN does the entry referencing it push - records never point at blobs the server can't serve.
```

> **Presigned upload means the ASP.NET server never proxies file bytes** - it stays a small
> metadata API regardless of photo volume.

> **Hygiene:** contentType allow-list (JPEG/PNG/HEIC/PDF), server-verified size on commit,
> per-account storage quota (generous free tier, metered like LLM usage), **orphan sweep** (blobs
> unreferenced by any live record + grace period -> deleted), and account deletion purges the
> whole prefix.

Note the two different presign lifetimes the docs specify: **upload ~15 min**, **download
~10 min**. They are not the same number; do not collapse them into one constant.

## What to build

1. **`POST /blobs/begin`**: dedupe by `(account_id, sha256)` -> `exists`; otherwise a presigned
   PUT valid ~15 min. Enforce the **content-type allow-list** (JPEG/PNG/HEIC/PDF) and the caps -
   **25 MB images, 10 MB PDFs**, which is a per-type cap, not one number. Over quota -> `429`.
2. **`POST /blobs/commit`**: **verify the object exists in storage and that its size matches what
   `begin` was told**, then insert the `blobs` row. A commit for an object that was never uploaded,
   or whose real size differs from the declared one, must not create a row - that is the whole
   point of a separate commit step.
3. **`GET /blobs/{sha256}`**: `302` to a presigned GET, TTL ~10 min. **`404` when the blob is not
   owned by this account** - never `403`, and never a redirect to another account's object. This
   is the cross-account isolation check.
4. **Per-account storage quota**, metered. Generous free tier; the number is yours to choose and
   to state in your report, but it must be configurable and it must be enforced at `begin`.
5. **Orphan sweep**: blobs unreferenced by any live record, past a grace period, are deleted from
   both the index and storage. A blob whose referencing record was tombstoned **within** the grace
   period must survive - undo is 30 days (hard rule 8), and sweeping a blob out from under a
   restorable record is data loss.
6. **Account deletion purges the account's whole prefix** - the `PRIMARY KEY (account_id, sha256)`
   exists for that.

## Tests (L2, against real Postgres via Testcontainers)

Count now: `dotnet test` **155**. Run it first, record the real number, and it must rise.

For S3 itself, use an **injected storage interface** with a real MinIO implementation and a
recording/in-memory double, so the suite does not require a running container for every case -
the same seam `IPayloadSchemaProvider` uses. Presign generation and expiry are then assertable
without the network.

1. **Dedupe**: the same sha256 twice for one account returns `exists` the second time and inserts
   **one** row. The same sha256 for **two different accounts** returns `upload` for both and
   creates **two** rows - content addressing dedupes *per account*, not globally.
2. **Caps**: 25 MB image accepted, 26 MB rejected `413`; 10 MB PDF accepted, 11 MB rejected `413`.
   **Assert the per-type boundary**, not one shared limit - a single cap passes a lazy test and
   ships the wrong contract.
3. **Content type**: a type outside the allow-list is refused, with the documented status, not a
   500.
4. **Commit verifies**: commit without an upload -> no row and a non-2xx; commit where the stored
   object's size differs from the declared size -> no row. **Assert the absence of the row**, not
   just the status code.
5. **Cross-account `404`**: account B requests account A's sha256 -> `404`, and **no presigned URL
   is generated at all**. Assert the storage double was never asked - a `404` returned after
   minting a URL has already leaked it into logs and traces.
6. **Presign expiry**: the upload URL expires ~15 min and the download URL ~10 min. Assert the two
   are **different**.
7. **Quota**: `429` once the account is over, and the response does not create a row.
8. **Orphan sweep**: an unreferenced blob past the grace period is deleted from index **and**
   storage; a blob referenced by a live record is not; **a blob whose record was tombstoned one
   day ago is not**.
9. **Account deletion** purges the prefix - assert both the index rows and the storage objects.
10. **No presigned URL, credential or storage secret appears in any log line** (hard rule 12),
    asserted against captured log output the way `backend/tests/.../Logging` already does.
11. **The new migration applies and rolls back.**

### Vacuous-assertion traps for this task

- Asserting a status code without asserting **what changed in the database**.
- A dedupe test with one account only - the per-account half is the part that can be got wrong.
- Testing the size cap with one number, so images and PDFs share a limit.
- A cross-account test that asserts `404` but not that the URL was never minted.
- An orphan-sweep test with no *surviving* case. A sweep that deletes everything passes a
  delete-only test.
- Mocking the repository and asserting the mock. These are L2 tests against real Postgres.
- Asserting `expiresAt` is "in the future" rather than asserting the two lifetimes differ.
