## The Russian traps, all of which have shipped here before

- **Plural rules are not optional.** `1 запись / 2 записи / 5 записей` - three forms, via String
  Catalog plural variations, never a composed string. `L10n.entriesExcluded` is the working
  example.
- **A `%@`/`%lld` that receives runtime data must not sit inside a case-governed phrase.** This has
  shipped **twice**: P1.4's `"%@ spend"` → `"%@ расходы"` rendered "АВГУСТ РАСХОДЫ"; P4.7's
  `"from your %1$@, %2$@"` → `"с вашего %1$@, %2$@"` rendered "с вашего телефон Android", because
  `с вашего` governs the genitive and a server-supplied device name cannot be declined. A **count**
  in a plural variation is fine - that is exactly what variations are for. A **currency code or a
  rate** dropped into a phrase is not.
- **`Text(_: String)` does not localize.** Any expression that produces a `String` renders its
  English key even when the catalogue holds the translation, and **the localization gate cannot see
  it** because the key is present. Four instances are recorded at the top of `L10n.swift`. The
  shape is always runtime data and copy sharing one expression - which is precisely what a rate
  input's label is.
- **Short strings expand worst.** Russian runs 20-30% longer and `Fix` → `Исправить` is 3x. A
  manual-rate action sitting on the conversion card's trailing edge is exactly the kind of affordance
  that overflows and truncates - and a truncated next step breaks hard rule 7.
- **The decimal separator.** A Russian locale types `4,2706`. The rate field must accept what the
  user's keypad produces; a parse that only accepts `.` silently rejects a correct rate.

### Vacuous-assertion traps named for this task

- Asserting a view **exists** without asserting its **text** - the classic way a localization bug
  stays green.
- A manual-rate test whose entry is dated **today** (`rateDate` then passes for the wrong reason).
- Asserting the footnote's count is in the string rather than the whole rendered phrase (see 4).
- A "no toast" test that never actually performs the backfill it claims to observe.
- `#expect(true)`, or asserting only that a call did not throw.
- Adding an XCUITest that only re-proves something a package test already covers. If a check
  belongs at L1, put it at L1 - P4.5's brief demanded a UI test that would have been vacuous, and
  the agent was right to refuse it. **If you think a required check here is wrong, say so in your
  report with your reasoning rather than writing a hollow test.**
