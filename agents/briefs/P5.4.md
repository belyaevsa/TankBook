## Why this endpoint is allowed to exist at all

**`POST /import/parse` is the ONE endpoint permitted to read what a field means.** `CLAUDE.md` hard
rule 9 was amended on 2026-08-27 to name it, because one parser serving every client and fixable by
deploy rather than App Store release was judged worth the cost. **Read rule 9 before you start** -
it lists the five properties that keep this from becoming a general domain server, and they are
requirements, not commentary:

- **Pure function.** It returns *candidate* records and **commits nothing**. The device reviews,
  edits and writes. No account state changes, ever.
- **Stored, deliberately** - the file and its parse result live in blob storage so a review can be
  resumed, **purged after 30 days** (`docs/SECURITY.md` → Import files at rest). This is the
  opposite of `/extract`, which stores nothing; both are signed off and neither licenses the other.
- **Works signed out.** No bearer required. Import must not require an account, or the exception
  drags hard rule 1 further than was agreed. Store under the device identity when there is no
  account.
- **Logs shape only.** Format, row counts, error counts. **Never** a station, note, amount or
  coordinate (hard rule 12).
- **It does not spread.** This licenses import parsing and nothing else.

## The fixture is real, and reading its README first will save you a rewrite

`Spike/ImportFixtures/mfm/` is a **genuine export** from the product owner, committed 2026-08-27.
**Read `Spike/ImportFixtures/mfm/README.md` before writing a parser.** Five things in it break a
first-attempt reader:

1. **The header is on line 2.** Line 1 is a title (`My Fuel Manager - Fuel`). A standard CSV reader
   takes it as the header and yields one column.
2. **The delimiter is `;`**, not a comma.
3. **Dates are `M/D/YYYY`** (`8/24/2026`) and **ambiguous** against `D/M/YYYY` for any day <= 12.
   The file contains such dates. **Do not guess** - this is the F6 ask-once-per-file question and
   guessing silently shifts history by up to eleven months.
4. **There is no unit-price column.** `fuel.csv` has `Fillup volume` and `Total price` only, so
   price per litre is **derived**.
5. **`Fuel` is a numeric code**, not a name (`1`, `2`; `00100003` on the vehicle). It does not map
   to `FuelKind` by string comparison.

Also: `Tank status after fillup` is `F`/`P` with a separate `%` column (→ `tankLevelAfterPct` and
the full-tank flag); `Currency` reads `USD` on **every** row regardless of where the fuel was
bought, so it is a **default the user corrects**, never a fact (hard rule 13).

**Each file uploads separately.** `fuel.csv` must parse **alone**, without `vehicles.csv` present.

### The defect in the fixture is deliberate. Do not clean it.

One Volvo row records **odometer 9** (with 68 L), another **11 436**, while that car otherwise runs
71 449 → 121 727. A naive importer computes a 121 718 km span and reports **3.4 L/100km for a
Volvo**. That is a real user's real typo and it is the most valuable row in the file.

**Do not special-case it, do not drop it, and do not "fix" it.** Parse it as it stands and let it
reach the client, where the preview's derived-consumption figure is what catches it
(`docs/JOURNEYS.md` F6a). A parser that silently repairs its input hides exactly the failure the
product is designed to surface.

## What to build

1. **`GET /import/formats`** - public, ETag'd, server-driven. Today it lists MFM. **The client
   renders whatever this returns**, so a format missing here is a format that does not exist.
2. **`POST /import/parse`** - multipart, <= 8 MB, `format` **declared by the user** (never sniffed).
   Returns `{ importId, format, scope: "vehicle", candidates[], unparsed[], ambiguities[] }`.
3. **Ambiguity is returned, never resolved**: the `M/D/YYYY` vs `D/M/YYYY` question and the
   currency default come back in `ambiguities` with the row counts they affect. The client asks
   once per file and applies the answer.
4. **Unparseable rows do not fail the file**: they come back in `unparsed` with a **reason**, and a
   partial parse is the normal outcome (F6, hard rule 8).
5. **Storage + `GET`/`DELETE /import/{importId}`**, and the **30-day purge job** on the
   `AccountPurgeHostedService` pattern.
6. **Commit the parse output as a fixture** - `Spike/ImportFixtures/mfm/parsed.json` or similar -
   so the iOS side can later assert the engine result offline, the way `vision-ab/*.json` lets the
   corpus A/B score without a model call. State the path in your report.
