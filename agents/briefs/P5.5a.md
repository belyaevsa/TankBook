## The rule this task exists to serve

`docs/SCHEMA.md` → Backup format, and the section **"Scope: a user-held export is PER CAR"**
(decided 2026-08-27), verbatim on the point that matters:

> A user exporting their data is exporting **one car** - its `Vehicle`, that car's entries of every
> type, its reminders and tariffs, the stations those entries reference, the matching attachments,
> and **the tombstones for all of it**.

> **So `manifest.json` declares its `scope`, and a reader must branch on it.** This is the same
> failure the catalog wire had before P6.12: a consumer that cannot tell *"here is everything"* from
> *"here is a part"* will treat a part as everything - and here that means importing one car's
> archive as a full restore, leaving a garage that looks correct and is silently missing every
> other car. The scope marker is **mandatory on every archive**, never inferred from
> `vehicleCount == 1` (a one-car user's full account and a one-car export are indistinguishable by
> count).

**That last parenthesis is the load-bearing sentence of this task**, and it is the mutation you
will be asked about: an implementation that infers scope from the count passes every happy-path
test and is wrong for exactly one user - the one with a single car, who is also the most common
early user.

## The archive, from `docs/SCHEMA.md`

```
manifest.json   { schemaVersion: 1, scope: "vehicle" | "account", vehicleIds: [...],
                  exportedAt, appVersion, vehicleCount, entryCount }   // always readable
data.json       { vehicles: [...], entries: [...], reminders: [...], stations: [...], tariffs: [...] }
                // exact shapes above, tombstones included; enums as strings; dates ISO-8601 UTC
attachments/    content-addressed blobs (sha256 filename) referenced by Attachment.file
```

- **`manifest.json` is always readable** even when the rest is not - the restore UI reads it first.
  If the archive is passphrase-protected, the manifest must still open.
- **Additive evolution only** (new optional fields); a `schemaVersion` bump needs a migrator.
- **Optional passphrase (AES) at export time - never required.** A mandatory user-held key is a way
  to lose your own data.

## What to build

1. **The writer**: given a vehicle id, produce the archive above - that car's `Vehicle`, its entries
   of **every** type (`FillUp`, `ChargeSession`, `ServiceRecord`, `Expense`), reminders, tariffs,
   the stations its entries reference, its attachments, and **every tombstone**.
2. **The reader**: parse an archive, **branch on `scope`**, and **refuse to treat a `"vehicle"`
   archive as an account restore**.
3. **Rejection is whole, never partial.** A truncated, corrupt or schema-failing archive imports
   **nothing** and leaves the app as it was - a partially applied archive is worse than a stale one,
   the same rule as the catalog pack and remote config.
4. **The optional passphrase path**, both directions, with an unprotected export still opening.
5. **A v1→v2 migrator fixture** proving additive evolution works.

## Tests

`cd ios && swift test` is **725**. Run it first, record the real number, and it must rise. Use a
real temp directory, not a mocked filesystem - the atomic write and backup-exclusion behaviour is
part of what is under test.

1. **Round-trip carries tombstones.** Export a car with deleted entries, re-import into an empty
   repository, and assert the **tombstones are present**. A tombstone that does not survive is a
   deletion that comes back (hard rule 8), and it is the easiest thing here to leave untested
   because nothing visible is missing without it.
2. **Round-trip carries attachments** - bytes and their `sha256`, not just the reference.
3. **Scope, both directions**: a `scope: "vehicle"` archive round-trips to exactly one car and
   **carries no other car's data** - assert the **other car is absent**, not that the count is 1.
   And a reader **refuses** to treat a vehicle archive as an account restore.
4. **Scope is read, never inferred.** Export from a garage holding **one** car, and assert the
   manifest still says what it is and the reader still branches correctly - the case where
   `vehicleCount == 1` for both meanings.
5. **Every entry type** is exported and re-imported, not just `FillUp`.
6. **A corrupt archive is rejected whole**: after a failed import, assert the repository is
   **unchanged** - not merely that an error was thrown.
7. **Passphrase**: protected export round-trips; an unprotected one still opens; **the manifest
   reads without the passphrase**.
8. **v1→v2 migrator fixture** upgrades and round-trips.
9. **Atomic write**: no `.tmp` residue, and the final file parses.

### Vacuous-assertion traps named for this task

- Round-tripping only entities that happen to have no optional fields set.
- Asserting a **count** where the point is **absence** (test 3).
- A corrupt-archive test that checks the throw but never re-reads the repository (test 6).
- Skipping test 4 because "one car works anyway" - that is the exact case the count-inference bug
  gets right by accident and wrong in meaning.
- Writing a second entity encoder instead of using `PayloadCodable`, which then drifts from sync.
- `#expect(true)`, or asserting only that a call did not throw.
