## The rule this task exists to serve

`docs/ERRORS.md` → Vehicle catalog updates, verbatim - and read the first sentence twice:

> The catalog is curated server-side and the server is master, but **every failure here is
> invisible**: the app always has a usable catalog (bundled seed pack at minimum), so there is
> nothing the user could do and nothing worth interrupting them for.

| Condition | Shows | Next step |
|---|---|---|
| Pack fetch fails (offline, 5xx, timeout) | **Nothing.** Suggestions keep working from the pack already on device; retry with backoff | Nothing to do |
| Pack fails validation, or is malformed | **Nothing.** Rejected whole - never partially applied - previous pack stands, logged at WARN | Nothing to do |
| Pack `packVersion` older than the one held | **Nothing.** Ignored (rollback protection) | Nothing to do |

**That is why this task adds no string.** Hard rule 7 says every error names its next step; here
there is no error surface at all, because there is no next step a user could take. A notification,
banner or toast added by this task is a bug.

`docs/SYNC.md` → Reference data, the layering:

| Layer | Source | Survives |
|---|---|---|
| **1 · Bundled seed pack** | Compiled into the app bundle | Everything. Changed only by an App Store release |
| **2 · Cached pack** | Last successfully fetched + validated pack | Restarts, offline, backend outage |
| **3 · Server pack** | `GET /catalog?since_version=<n>` | Until the next fetch |

> **On overlap, the server wins.** A cached entry with the same identity as a server entry is
> **replaced, not merged**.

> **But this never touches user data.** Catalog values are *suggestions copied into the `Vehicle`
> row at Add-car time*, and **no `Vehicle` ever references a catalog entry by id**. So a corrected
> pack changes what the *next* car pre-fills and **never rewrites a car already in someone's
> garage** - including a value the user typed over. "Server is master" governs the catalog, not the
> garage.

**Those two paragraphs pull in opposite directions and both must hold.** The master rule and its
limit are the pair this task is judged on.

## The wire, as the server actually shipped it (P5.6, merged today)

`GET /v1/catalog?since_version=<n>` - **public, no bearer.** camelCase, ETag'd, `If-None-Match` →
`304`. Body:

```json
{ "packVersion": 7,
  "entries": [ { "id": "…", "make": "Volvo", "model": "V60", "generation": "II",
                 "years": [2018, 2024], "powertrain": "…", "fuelKinds": ["petrol95","diesel"],
                 "tankCapacityL": 71, "batteryCapacityKwh": null } ] }
```

Read `backend/src/Tankbook.Api/Catalog/CatalogEndpoints.cs` for the exact shape rather than
trusting this summary. Notes that matter:

- **`years` is an inclusive `[start, end]` pair**, not a half-open range.
- A `since_version` at or above the current version returns an **honest empty delta** (or `304`) -
  `entries: []` with the current `packVersion`. That is not an error and not an empty catalog.
- A missing `since_version` returns the **full pack** by documented default.
- **`fuelKinds` is an OFFER SET, not a car's fuel** (`docs/SCHEMA.md`): `V60 → [petrol95, diesel]`
  means the model line is sold as petrol *or* diesel. Add car must present it as options to choose
  from and **must never copy the whole set onto a `Vehicle`** - a car claiming to burn both petrol
  and diesel does not exist. You are not changing Add car, but do not build an API that invites it.

## What to build

1. **The cached layer**: `Application Support/Tankbook/catalog.cache.json`, written **atomically**
   (temp + rename, so a crash mid-write cannot leave a truncated pack) and **excluded from
   backups** - it is regenerable and it is not user data. `ConfigCache` shows both.
2. **Three-layer resolution** behind the existing suggestion query: bundled seed < cached pack <
   server pack, with **overlapping identities replaced, not merged**.
3. **The fetcher**, over the injected transport, sending the held `packVersion` as
   `since_version`, handling `304` as "nothing to do", decoding the body exactly.
4. **Validation, whole or not at all.** A malformed or schema-failing pack is rejected **entirely**
   and the previous cache still serves. A partially applied pack is worse than a stale one.
5. **Rollback protection**: a pack whose `packVersion` is not greater than the one held is
   ignored.
6. **Never launch-blocking**: background and throttled. A cold start uses whatever is already on
   disk. Hard rule 1 - Add car works offline, day one, with no account.
7. **The curation feedback counter**: a catalog miss is counted **without the typed text**
   (`SYNC.md` → Curation feedback loop, hard rule 12). A count is loggable; what the user searched
   for is not, at any level, in any build.

## Tests

`cd ios && swift test` is **671**. Run it first, record the real number, and it must rise. Use real
files in a temp directory for the cache, not a mocked filesystem.

1. **Day one, offline**: no cache, no network - the **bundled seed pack still answers** Add-car
   suggestions. This is hard rule 1 and it is the test that matters most.
2. **The master rule**: a server entry overlapping a cached/bundled one **replaces** it - assert
   the *replaced field value*, not just the entry count.
3. **The master rule's limit**: a corrected pack **does not rewrite a `Vehicle` already saved**,
   including a field the user typed over. Save a vehicle, apply a pack that changes that model's
   figures, assert the saved vehicle is **byte-identical**. This is the one that protects a user's
   override, and it is the easiest to leave untested because nothing appears to happen.
4. **Malformed pack rejected whole**: the previous pack still serves afterwards - query it and
   assert the OLD values, not merely that an error was thrown.
5. **Rollback**: `packVersion` lower than held is ignored; **equal is ignored too** (test both -
   `>` vs `>=` is the likely bug).
6. **Truncated cache falls back to the seed pack** rather than failing.
7. **Atomic write**: a cache file is never left partially written - assert the temp path is not the
   final path and that the final file parses after a write.
8. **Excluded from backups**: assert the resource value is actually set on the written file.
9. **Every failure is silent**: fetch failure, 5xx, malformed body and an old pack each leave the
   suggestion surface working and produce **no user-facing error value** anywhere in the returned
   API.
10. **A catalog miss is counted without the typed text** - assert the recorded value contains a
    count and **not** the search string.

### Vacuous-assertion traps named for this task

- Asserting "an error was thrown" for the malformed pack without re-querying to prove the old pack
  still serves.
- Testing rollback with only a *lower* version, never the equal one.
- A "server wins" test that asserts entry counts rather than the replaced field.
- Skipping test 3 because "nothing happens" - that is the whole point of it.
- Mocking the filesystem. Use a real temp directory; the atomic-write and backup-exclusion
  behaviour is the thing under test.
- `#expect(true)`, or asserting only that a call did not throw.
