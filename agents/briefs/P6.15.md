## All three were found by a human opening a screenshot. No test saw any of them.

That is the point of this task: they are appearance defects, and XCUITest asserts behaviour.

### (a) Double header on the preview
A nav title "Импорт" sits above the screen's own "Просмотр импорта / Назад / Отмена" row - two
stacked headers. `design/screens/ImportPreview.dc.html` draws **one**. Match the artboard.

### (b) RU action labels hyphenate mid-word
On the review rows: «Испра-вить», «Импортиро-вать как есть», «Пропу-стить». Three actions do not
fit one line in Russian - the documented 20-30% expansion doing what it always does to short
strings (`Fix` → `Исправить` is 3x). Fix by letting the row wrap, stacking, or shortening the
Russian - **never by truncating**, because a clipped next step breaks hard rule 7.

### (c) An unreadable row shows our own wire JSON
A row that could not be parsed renders `"entityType": "fillUp",` - an internal representation the
user has never seen. `docs/JOURNEYS.md` **F6b** does say the raw line is the right answer for
exactly this case, but it means **the line the user's file contained**, not our envelope. Show the
original delimited source line (the server returns it; see `unparsed[].row` in `docs/API.md` →
Import parsing), or if it is genuinely unavailable, say so in words rather than showing JSON.
