## What to build

1. `appUpdate` as an **optional** member of `ConfigDocument`, decoded from
   `{ "minSupportedVersion": "1.2.0", "latestVersion": "1.4.0" }`. Absent is legal and common.
2. A version type that compares **numerically per component**, not lexicographically, and that
   **fails to parse** rather than guessing on anything that is not dotted numerics.
3. The derived requirement, exposed on the resolved snapshot as a **single typed value** -
   `.none` / `.recommended` / `.required` - computed from the running app version and the two
   thresholds, per CONFIG.md's table:
   - running `>= latestVersion` -> `.none`
   - `>= minSupportedVersion` and `< latestVersion` -> `.recommended`
   - `< minSupportedVersion` -> `.required`
4. The running version is **injected**, never read from `Bundle.main` inside core. Tests must be able
   to construct any version without a bundle. This project's standing rule is injected dependencies,
   not singletons.

## The invariants, and the mutations that must kill them

Write the tests so that each of these FAILS when the code is broken. Then actually break it,
confirm the failure, and restore. Report both results.

1. **Numeric comparison, not lexicographic.** `1.10.0` is newer than `1.9.0`; a string compare says
   the opposite. **This single pair is what separates the two implementations** - a test set without
   it is vacuous no matter how many cases it has. Mutation: replace the comparison with `<` on
   strings and confirm a test fails.
2. **Fail OPEN, never closed.** An absent `appUpdate`, a malformed `minSupportedVersion`, a malformed
   `latestVersion`, or a running version that will not parse, each resolve `.none`. Mutation: make
   any of them resolve `.required` and confirm a test fails. CONFIG.md's reason matters: failing
   closed would let one bad string withdraw sync from every install at once.
3. **Two thresholds, one derived value.** There is no `severity` field and must not be one - it could
   contradict its own thresholds. Assert the three outcomes at the boundaries, including **equality**
   (running == minSupportedVersion is `.recommended`, not `.required`; running == latestVersion is
   `.none`). Off-by-one at a boundary is the likeliest real bug.
4. **A document with an unknown key still applies.** The existing partial-unknown behaviour must not
   regress - add `appUpdate` alongside an unknown sibling and assert the rest still parses.

## Vacuous-test traps, named

- Testing only `1.0.0` vs `2.0.0`. Every wrong implementation passes that.
- Asserting the enum's raw value rather than the decision (`#expect(req == .required)` where the
  fixture was built to produce `.required` by construction).
- A "malformed" fixture that is still valid dotted numerics, e.g. `"1.2"` - decide deliberately
  whether two components parse, document the choice, and test the case you did NOT allow.
