## The rule that decides the whole design

`docs/JOURNEYS.md` **J9**, verbatim:

> ⚠ **False alarms erode trust fastest** → thresholds conservative, seasonality-aware, always
> dismissible with a reason.

> **Success metric:** anomaly cards acted on or explicitly dismissed ≥70% (**ignored cards = noise
> signal**).

**So the engine's job is to stay quiet.** A detector that fires often is not a better detector; it
is the failure mode the journey names. Everything below follows from that.

`docs/VISION.md` fixes the comparison, and it is not "this month vs last month":

> **anomalies compare the rolling value against the trailing-12-month (seasonally fair) baseline.**

That is the seasonality answer: a winter rise is only an anomaly if it exceeds what *last* winter
did. A naive month-over-month rule fires every November for every user in a cold country, which is
the single most likely way this ships wrong.

## What to build

1. **A pure anomaly detector**: given a vehicle's segments (or the values the engine derives from
   them), return either nothing or a described anomaly - the metric, the magnitude, the window
   compared, and the baseline it was compared against. **A value type, testable without a view**
   (the `TabBarMetrics` / `PumpPhotoGate` precedent).
2. **Seasonally fair comparison**: rolling value vs the **trailing-12-month** baseline, per
   `docs/VISION.md`. Not month-over-month.
3. **Conservative thresholds**, stated as named constants with the reasoning beside them, so a
   future change is a deliberate act rather than a tweak.
4. **Dismissal suppression**: a dismissed anomaly, with its reason, does not re-fire for the same
   cause. Model the reason as data (the `ReminderLifecycle` precedent); **persisting the dismissal
   is fine - persisting the verdict is not** (hard rule 2).
5. **Insufficient data yields nothing.** The consumption engine already has a floor of 3 segments;
   an anomaly needs at least a full baseline to compare against. **Silence is the correct output**
   for a new user, and it must be tested as an outcome rather than assumed.

## Tests

`cd ios && swift test` is **804**. Run it first, record the real number, and it must rise.

1. **Winter never false-fires.** Build a fixture whose consumption rises every winter and returns
   to baseline every spring, across more than two years, and assert **no anomaly** in any winter.
   This is the headline test and the one the journey exists to prevent.
2. **A real drift does fire**: a sustained rise that exceeds the trailing-12-month baseline is
   detected, with the correct magnitude.
3. **Dismissal suppresses**: after a dismissal with a reason, the same cause does not re-fire;
   assert it stays suppressed across a recompute.
4. **A different cause still fires** after that dismissal - otherwise "dismiss" silently becomes
   "mute everything", which is the opposite of teaching the model.
5. **Insufficient history yields nothing**, not a low-confidence guess.
6. **The D1-D4 golden vectors are unaffected** - the consumption numbers must not move.

### Vacuous traps

- A month-over-month comparison dressed up as seasonality (it passes test 2 and fails test 1).
- Testing only that an anomaly fires (test 1 is the harder and more important half).
- Persisting the verdict instead of the dismissal, which breaks hard rule 2 and goes stale the
  moment an entry is edited.
- A threshold picked so nothing in the fixtures fires - assert test 2 to stop that.
- `#expect(true)`.
