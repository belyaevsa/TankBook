- **`.timerJob`** - no timer cycle exists anywhere in the app. The P6.8b commit message claimed
  "launch, foreground and timer cycles"; the timer half is fiction.
- **`.blobPrefetch`** - there is no prefetch path at all. `LazyBlobFetcher` is an on-demand fetch
  built in `AppSync.makeBlobFetcher`; the string `prefetch` appears in `ios/App/Sources` and
  `ios/Sources` **only** in `PowerState.swift`. So the "blob prefetch defers" rule in
  `docs/SYNC.md`'s table is enforced by nothing.
- **`.catalogPackFetch`** - `VehicleCatalogUpdater` consults the policy correctly at
  `VehicleCatalogUpdater.swift:156`, but the app never instantiates it.

The three that ARE wired, for contrast: `.syncCycle` (`SyncCoordinator.swift:74`), `.blobUpload`
(`SyncEngine.swift:241`), `.ratePackRefresh` (`RateStore.swift:135`).

`LowPowerModeTests.policyDefersEveryOpportunisticWorkKindWhileTheModeIsOn` iterates all six and
so paints the split as complete.

### (b) `RateStore` bypasses the single power seam


`RateStore.init` declares `powerState: any PowerStateProvider = ProcessInfoPowerState()`
(`RateStore.swift:50`) and the app passes nothing, so it takes the default. Production behaviour
is identical - but `-forceLowPower` cannot reach it, so **the one consumer whose deferral no test
can force is the one `AppPower.swift`'s doc comment claims to cover**: "hands both to every
consumer ... the sync coordinator, the blob gate inside the engine, **the rate store's refresh**,
and the Settings status surface."

`AppSync` is wired correctly and is your model - `TabRoots.init` already does
`AppSync(configService:powerState:resumer:)` with `power.powerState`, and already does
`AppRates.resumer = power.resumer` two lines later.

### (c) Two `ConfigUpdateSurfaceTests` are vacuous as written

`requirementIsStableWhileAFetchIsInFlight` (line 289) and
`snapshotTakenBeforeRefreshIsUnaffectedForTheRequirement` (line 323) both stall on a `FetchGate`
**inside `GatedConfigFetcher.fetch()`** - that is, **before the document is fetched at all**. So
there is never a fetched-but-uncommitted document, and the mutation they name (evaluating the
requirement against an in-flight fetch instead of the held snapshot) **cannot be caught by
either**. Their `during == before` assertion holds trivially.

**The correct shape already exists in the same file**:
`requirementResolvesFromTheHeldSnapshotNotAnInFlightFetch` opens the fetch gate immediately and
stalls the **health probe** instead (`ProbeGate` + `GatedHealthProber`, plus a pending document on
a different allowlisted host `https://cdn.tankbook.live` so the health gate is reached), producing
a genuine fetched-but-not-committed state.

## What to build

1. **Wire (b).** Give `AppRates` the app's injected `PowerStateProvider` and pass it to
   `RateStore`. **The trap**: `AppRates.store` is a lazy `static let`, so it is built on **first
   access**, and an injection set after that is silently ignored. Set the state in `TabRoots.init`
   next to `AppRates.resumer = power.resumer`, and make the seam **fail loudly or provably early**
   rather than silently taking the default - e.g. a `configure(powerState:)` that must run before
   the store is first touched, with a test that pins the ordering. Say plainly in a comment which
   guarantee you chose.

2. **Make the enum stop implying coverage (a).** Two parts, both required:

   - **`docs/SYNC.md` -> Low Power Mode**: mark blob **prefetch**, the vehicle **catalog pack
     fetch** and any **repeating timer job** in the deferral table as **policy present, call site
     not wired** - the policy is written and tested, the work does not yet exist in the app. Keep
     the rows: the rule is right and is what a future call site must obey. Do not delete the enum
     cases; do not invent the work.
   - **A guard that pins the split.** Split
     `policyDefersEveryOpportunisticWorkKindWhileTheModeIsOn` so the wired kinds and the unwired
     kinds are asserted as two named sets, and add a **source-scan guard** over
     `ios/Sources/TankbookCore/**` and `ios/App/Sources/**` that pins **exactly which cases have a
     production call site**. It must fail when a case moves between the sets in either direction -
     when someone wires `.blobPrefetch` and forgets the doc, and when someone deletes a call site.
     A text scan is acceptable; **say plainly in the test what it cannot see** (it cannot see a
     case passed through a variable).

     This is the point of the task. **Enumerate the class, not the case in front of you** - a
     guard written while fixing a defect tends to cover exactly that defect, which is how the
     contrast guard was too narrow twice in one day (see `HANDOVER.md`).

3. **Rebuild the two vacuous tests (c)** on the `ProbeGate`/`GatedHealthProber` pattern already in
   that file, so each stalls **after** the document is fetched and validated and **before** it is
   committed. Keep their names and their stated claims; they must now be able to fail.
