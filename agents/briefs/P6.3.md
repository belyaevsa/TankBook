## Read `docs/API.md` → "The device's side of `/extract`" FIRST. It is normative and it already
## answers the question you are about to ask.

You will notice that the corpus measured the gateway at **median 6.5-8.3 s, max 40 s**, and that
the budget is **3 s**. That is not a contradiction, and the doc says so in the same paragraph:

> **The budget is about the user's next step, not about aborting the work** - and the arithmetic
> says it has to be. At a realistic 1 Mbit/s upstream, even a 250 KB rendition takes ~2 s to upload
> before the model has seen a pixel, so a hard 3 s abort would cancel almost every request on a
> mobile link and make the whole tier useless where it is needed most. So: **at 3 s the UI moves
> on; the request itself may finish in the background.**

**So do not implement the budget as a cancellation.** At 3 s the sheet stops waiting and tells the
user they can carry on with what was read locally. The request keeps going.

## What to build

1. **Downscale and compress before upload** (`API.md` rule 1): a long-edge-bounded, JPEG-compressed
   rendition, starting at **long edge 1600 px**. The 4 MB envelope is a ceiling, not a target.
2. **The 3 s UI budget** (rule 2): the on-device result is already on screen - the app never waits
   on the gateway to show the card (F4). At 3 s, show the message that **names the next step**
   (hard rule 7): carry on with what was read locally.
3. **The late answer, bound by hard rule 13 and F4**: it may fill **only fields that are still
   blank and untouched**, renders as a **suggestion** (not a locked value), and **nothing arrives
   after save**.
4. **Consume `SyncServerError`, do not re-classify.** P6.11 already shipped the classification
   (`402` → `.tierRefused`, `429` → `.rateLimited(retryAfterSeconds:)`, `426` → `.upgradeRequired`,
   unknown 4xx → `.refused(status:)`) and its surface. Reuse it.

## The two things the corpus says about this gateway, which shape the UX

`docs/EXTRACTION.md` (P4.12):

- **It is far better than the rules parser** - receipts 84/96 against 46/96, pump 31/46 against
  1/46 - **and its failures are silent**: five receipts came back with volume and price **swapped**,
  which passes the arithmetic cross-check because `a x b == b x a`.
- **It is stochastic**: `pump-009` flipped between correct and shifted across identical runs.

**So the gateway suggests and is cross-checked; it is never trusted.** A confident swap is worse
than the parser's nil (hard rule 13). Anything you fill from a late answer stays a suggestion the
user can see and change.

## Tests

`cd ios && swift test` is **815**; `xcodebuild test` on `iPhone 17` is **141**. Both must rise.

1. **The 3 s budget fires against an injected slow transport** - and **the request is NOT
   cancelled**: assert it completes afterwards. This is the test that distinguishes the correct
   implementation from the one the doc warns against.
2. **The sheet stays usable throughout** - the user can type while the request is in flight.
3. **A late answer fills a blank untouched field**, and **cannot overwrite a touched one**.
4. **Nothing arrives after save** (F4).
5. **The timeout message names its next step** (hard rule 7), EN and RU.
6. **No paywall or upsell is reachable from any capture flow** - assert absence.
7. **L5: compression must not cost accuracy.** Re-score the receipt corpus through the compression
   step with the **existing** `CorpusScorer` at the **existing** tolerance; hits may not fall below
   the recorded mark (receipts **88/175**). This is what stops "compress harder" quietly becoming
   "read worse".

### Vacuous traps

- Implementing the budget as a cancellation - it passes a naive "does it time out" test and makes
  the feature useless on a real connection.
- Asserting the timeout message exists without asserting its **text**.
- A late-answer test that never touches a field first (test 3's second half is the point).
- Re-scoring with a different tolerance or a different scorer - three committed engine comparisons
  depend on that one tolerance.
- `#expect(true)`.

## Two blind spots this codebase has shipped

- **`Text(_: String)` does not localise.** A *literal* is a `LocalizedStringKey`; an **interpolated
  `String`** is not, and the gate cannot tell them apart because no key is missing. **Six instances
  have shipped**, two this week. A timeout message with a duration in it is exactly this shape.
- **`swift test --filter <UITestName>` matches zero tests and exits 0.** XCUITests are invisible to
  the package runner; use `xcodebuild -only-testing:`.

Also: **Russian never puts the user in a past-tense verb** (it has no genderless past), and check a
translated term against the app's own domain vocabulary - both rules are in `docs/LOCALIZATION.md`
with the instances that produced them.
