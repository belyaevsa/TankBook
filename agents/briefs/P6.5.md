## What is ALREADY DONE - do not redo it

`docs/DESIGN.md` → Accessibility floor is the authority, and the **contrast half is finished**:

- `PaletteAccentGuardTests.accentContrastClearsAA` computes WCAG ratios for **every** accent on

Read that section before touching anything, and **do not weaken either guard**.

**The history that matters here**: this contrast guard was written **too narrowly TWICE, each time
while fixing the previous version of it.** The first looped over only the two accents that task
touched while `warn` sat at 3.82:1 in ~15 files; the second checked accent-on-background and missed
text-on-fill, where white on `warn` is **2.15:1** on a shipped button. Both looked complete, passed,
and left a worse case untouched.

**So the question for every check you add is not "does it catch the defect I found" but "what CLASS
is this defect in, and does my check enumerate the class?"**

## Named vacuous traps

- **A guard that enumerates only what you just fixed.** Named above; it has happened twice.
- Asserting a label **exists** rather than that it **reads correctly** - `accessibilityLabel` set to
  the raw number passes an existence check and fails a blind user.
- Dynamic Type "checked" by an XCUITest reading the accessibility tree: it reads the string a view
  was **given**, not the pixels drawn. A clipped label passes. Geometry assertions or screenshots.
- Tap-target checks on the accessibility frame of a container rather than the actual hit area.
