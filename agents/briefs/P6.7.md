## The decision this task implements (made by the product owner, 2026-08-27)

**`headlight` cyan encodes *electric*, and nothing else.** That was always what
`docs/DESIGN.md` said; the app drifted.

`docs/DESIGN.md`, verbatim:

> Semantic first: the two accents are not decoration, they **encode powertrain**. Everything that
> burns fuel is taillight red-orange; everything electric is headlight cyan.

> One accent per screen region. **A fuel card never shows cyan**, a charge card never shows
> taillight.

> `taillight` is meaning, not chrome: navigation bars, backgrounds, and tab bars stay neutral - the
> accent appears on numbers, entry markers, the capture button, and the cross-check lock,
> **nowhere else**.

**There are ~66 `Theme.Palette.headlight` uses across ~25 files, and only two are electric** - the
`vehicle.powertrain == .ev ? .headlight : .taillight` expressions in
`ios/App/Sources/CarSwitcher/CarSwitcherView.swift` and `ios/App/Sources/Trends/TrendsView.swift`.
Everything else is a button, a link, or a small icon.

**The root cause is that the design system has no interactive colour.** Both accents are reserved
by the rules quoted above, so there was nothing else to reach for. That is what this task fixes -
the sweep alone would just move the problem.

## What to build

### 1. The `action` token

Add to `design/tokens.json`, in the `color` object, **exactly these values**:

```json
"action": { "dark": "#8FB4D9", "light": "#2F6690" }
```

Contrast, already computed - do not re-derive, and do not substitute your own colour:

| | vs `midnight` | vs `dash` (card) |
|---|---|---|
| `action` dark `#8FB4D9` | **8.60:1** | **7.64:1** |
| `action` light `#2F6690` | **5.67:1** | **6.13:1** |

All four clear WCAG AA for body text (4.5:1), which `docs/DESIGN.md` → Accessibility floor makes
non-negotiable, and all four beat the existing accents' own ratios, so this is not a regression.

Then regenerate: `swift scripts/generate-theme.swift`. `Theme.generated.swift` is **generated** and
is excluded in `.swiftlint.yml` - never hand-edit it.

### 2. Re-point every non-electric use

Classify each of the ~66 sites into exactly one of three, and change it accordingly:

- **Electric** → stays `headlight`. Two sites are certain (the `powertrain == .ev` ternaries above).
  Any other genuinely electric one - a charging entry, a kWh metric, a charge-session marker -
  stays too. **Say in your report which ones you kept and why.**
- **Interactive** → `action`. A `Button`, a `NavigationLink`, a tappable row's chevron or its
  affordance icon - anything the user can press. `Button("Sign in")`,
  `Button("Delete again")`, `Button("Keep")`, `Text("View")`, `Button("Edit")` are all in this
  group.
- **Inert icon or decoration** → `inkSoft`. A leading SF Symbol that merely labels a row, a
  decorative rule, a non-interactive badge. `inkSoft` is the caption colour and is what these
  should always have been.

**When a site is genuinely ambiguous, choose `action` only if the thing is actually pressable.** A
coloured icon that does nothing is the bug this task is removing, not a style to preserve.

### 3. The rule, written down and enforced

- `docs/DESIGN.md`: add `action` to the palette table beside `taillight` / `headlight` / `warn`,
  and state the rule in the surrounding prose: **`action` is "you can press this"; it never
  appears on an entry marker or a metric**, because those two places are where powertrain is
  encoded and the channels must stay separate. Note that colour is still never the only channel
  (the accessibility floor already says so).
- **A test that fails when cyan escapes again.** Scan `ios/App/Sources` from disk for
  `Palette.headlight` and assert the set of occurrences equals an explicit **allowlist** of
  electric uses, file and reason. `AccuracyRatchetTests` reads repo files from disk via `#filePath`
  and is the precedent for a source-scanning test; the localization gate is the precedent for the
  idea. **This is the deliverable that makes the decision stick** - without it the 67th generic use
  lands next week and nothing notices.
