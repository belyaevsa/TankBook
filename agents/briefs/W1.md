## What to build

**S1 - skeleton**

1. `scripts/generate-site-tokens.swift` - reads `design/tokens.json`, writes
   `site/assets/css/tokens.generated.css`. Dark values on bare `:root`; light values inside
   `@media (prefers-color-scheme: light)`. Emit `color-scheme: dark light`. Spacing, radius and the
   hairline become custom properties too - the hairline opacity comes from `tokens.json`, never a
   literal. First two lines are a generated-file warning naming the source and the regeneration
   command, matching `generate-theme.swift`'s wording. Sort colour names so diffs are stable.
   **It must support `--check`**: re-render to memory, byte-compare against the committed file, and
   **exit 1 on any difference**, exit 0 when identical. This is the hand-edit guard.
2. `site/hugo.toml` - `baseURL = "https://tankbook.app/"`, `defaultContentLanguage = "en"`,
   `defaultContentLanguageInSubdir = false`, EN and RU language blocks, language-scoped menus,
   `enableRobotsTXT = true`, `disableKinds = ["taxonomy", "term", "rss"]`,
   `[markup.goldmark.extensions.typographer]` with `emDash` and `endash` both set to the en-dash
   character so a typed `---` can never render as an em-dash. Mount `../design/screenshots` to
   `assets/screenshots`; when you declare any mount you must restate the default mounts too, or they
   are dropped.
3. Layouts: `baseof.html`, `home.html`, `page.html`, `404.html`, `robots.txt`, and partials under
   `layouts/_partials/`. Hugo 0.146+ uses the flattened layout structure - no `_default/` directory.
4. CSS: `base.css` (reset, system font stack, type scale, tabular figures, focus rings,
   `prefers-reduced-motion`), `layout.css`, `sections.css`. **Every colour is `var(--token)`. A
   literal hex in a hand-written CSS file is a defect** - the web form of hard rule 5.
5. `head/css.html` concatenates and minifies all CSS and **inlines it in a single `<style>`**. There
   must be zero `<link rel="stylesheet">` in the output.
6. `.gitignore`: add `site/public/` and `site/resources/_gen/`.

**S2 - the landing page, both languages**

7. `content/_index.md` and `content/_index.ru.md` - all landing copy in front matter as structured
   params, including the FAQ as a list of question/answer pairs. Lift wording verbatim from the artboard.
8. Seven section partials under `layouts/_partials/sections/` in SITE.md's order: hero, doors,
   crosscheck, yourdata, powertrains, roadmap-teaser, faq. Footer lives in `baseof.html`.
9. `screenshot.html` partial - the only path to an `<img>`. It takes an explicit filename and an
   `alt`. It must call `errorf` when the resource is missing, when `alt` is empty, or when `alt` is
   the literal word "screenshot", so an undescribed or missing image is a **build failure**.
10. `i18n/en.toml` and `i18n/ru.toml` for chrome strings (nav, skip link, footer labels).

**The one rule that outranks the others:** in the "two doors" section, snap-it and type-it must be
**visually identical in weight** - same card, same accent, same title size, same image treatment.
Neither is a fallback. This is hard rule 15 and it is the reason the section exists.

Drop the footer line that reads "api.tankbook.app stays the backend" - infrastructure detail does not
belong in public chrome. Keep the pre-launch honesty line and `mailto:to@belyaev.live`.

## Vacuous-check traps for this task, named

- A `--check` flag that always exits 0 because it compares the file to itself after rewriting it.
  Render to memory, compare to what is on disk. Never write before comparing.
- An `errorf` guard in `screenshot.html` that never fires because the template also supplies a
  default `alt`.
- Declaring `hugo` succeeded when it emitted warnings and produced no `public/`. Check the file exists.
- Reporting `grep` "passed" when the pattern was wrong and it found nothing anywhere, including in
  files that should match. Sanity-check at least one grep against a string you know is present.
