# PU.76 — independent opinion on the row detector method

**Recommendation: spike the existing detector plus fast Hough turn first, as a falsifiable baseline; if its actual detections cannot recover the framing, train a compact one-stage oriented detector.** Do not spend the first training round reproducing a full scene-text architecture. This opinion uses the code, `docs/EXTRACTION.md`, and `docs/TASKS.md`; it does not use the parallel PU.76 research note.

The target is the **row quad consumed by the reader**, not merely an angle or loose detection. The heldout apportionment gives the relevant ceiling: the same hand windows yield **89 commits at 0.944** as upright bounds and **111 at 0.991** as quads. Its 33-cell detector-framing loss is larger than the 13-cell proposal loss. PU.66's three rotated-data Create ML retrains all failed the shipped reading gate; the hand-only round improved row presence yet made wrong readings. Thus training another upright-box model is a weak bet. PU.70 also establishes that a turned row can be returned as a *small* box (pump-302: detector width 0.10 of the frame, hand row 0.30). An angle cannot restore missing endpoints by itself.

| **1 — spike first** | **Keep the 31 MB detector; turn each proposal with `PumpRowDeskew.angle(of:)`.** Near-zero bundle growth and little integration work. The existing fast Hough estimator has 0.60° median and 1.97° p90 error against hand-quads, at about 3 ms per row on the reported Release Mac run. Extra per-row CPU and a false turn could create a wrong reading. | Offline, on the fixed heldout split, run the shipped boxes through the existing turn and compare **rotated IoU and reader commits** with (a) raw shipped boxes, (b) upright bounds of hand quads turned by the same estimator, and (c) hand quads. Keep proposal identities fixed. This separates angle quality from lost extent. If actual-box framing loss cannot fall below about 15 cells, or the live path cannot approach 65 commits with **zero wrong readings**, reject this as the solution; retain it as a control. Measure Release latency on an iPhone 12 before shipping. |

Falsify the family if framing loss stays ≥~15 cells or live cannot reach ~65 at zero wrong readings. |
| **3 — fallback learned candidate** | **Small instance-mask head plus a minimum-area rectangle per connected row region**, inspired by PixelLink's pixel-and-link instance segmentation. A dense boundary can be more forgiving than angle regression for reflective, skewed strips; a fitted quad can feed the existing warp. Use the same compact backbone/size target as rank 2. | Hand quads are only coarse region supervision, not digit-ink masks. Adjacent transaction and price rows can merge; reflection and bezel pixels can split or enlarge a mask. Mask output and grouping may dominate iPhone latency. | Rasterize the adjudicated train quads as row-instance targets, train one tiny mask/link model, and extract quads with deterministic connected components plus minimum-area rectangles. **Methods I would defer.** Full **TextBoxes++** is a valid single-pass quadrilateral detector, but its published scene-text scale and architecture are a poor starting size target; its useful idea is the oriented head in rank 2. **RRPN** (Ma et al.) and **Oriented R-CNN** use oriented proposals and rotated RoI processing. They add two-stage conversion and runtime work before this small row corpus establishes that a one-stage head is insufficient. This is an engineering inference from their architectures, not an iPhone benchmark. PixelLink likewise motivates rank 3 rather than requiring its full reference implementation.

**Gate before comparing methods.** Repin the train quads under one edge/endpoint rule, with disagreements adjudicated before fitting thresholds. Use pixel-space geometry, ordered corners and **rotated** IoU; the current upright-IoU gate does not measure the reader's crop. Report recall@0.7, false rows/photo, matched-row framing loss in the apportionment, live committed/correct/wrong cells, model bytes **relative to the 31 MB detector**, and end-to-end Release latency on iPhone 12. Do not promote a detector on detection recall alone: PU.66 already showed that more proposals can read fewer cells and create wrong ones. The ~65-cell target is a spike gate from PU.76, not a predicted result or a measured ceiling.

Verified: the arXiv preprint first appeared in 2017; 2018 is the publication year used here.

No model was trained or benchmarked for this opinion; the payoff and risk rankings are hypotheses to test with the experiments above.
